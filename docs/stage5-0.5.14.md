# 0.5.14 — 찾은 본문의 정확한 복구와 검사 범위 구분

4단계의 기록 재사용·이름/본문 연결 문제는 보류하고 5단계를 진행했다. 이 릴리스는 F25/F26의 아래 고정 이미지 시험군 인수와 F30의 실패 구간 설명 일부 보강이다. 5단계 전체 완료나 실제 SSD 복구율 상승을 뜻하지 않는다.

## 사용자에게 달라진 점

- 전체 바이트를 저장해도 문서 검사 한도 8MiB를 넘으면 ‘일부 내용’으로 분류하던 문제를 고쳤다. ‘파일 저장 · 문서 상태 미확인’과 ‘문서 검사 범위 제한’으로 안내한다.
- 미리보기 범위 제한, 실제 일부 본문만 저장, 문서 손상, 읽기 실패를 구분한다. 이전 버전의 `document.truncated` 기록도 검사 범위 제한으로 처리한다. 실제 부분 저장은 명시적인 `result.partial` 근거를 유지한다.
- 비압축 물리 구간 읽기에 실패하면 읽던 스트림 안의 요청 위치·요청 크기와 원본 읽기 위치를 진단에 남긴다. 상세 값은 기존 ‘확인 근거와 검사 범위’에 나타난다. 파일 본문 외에 MFT 등 관리 스트림을 읽는 중에도 발생할 수 있으므로, 화면에서는 요청 실패만 안내한다. 그 요청 전체가 손상됐다는 뜻은 아니며 정확한 손상 바이트 수는 미확정이다.
- 읽기 실패를 0으로 채워 성공 처리하지 않는다. 완료 파일을 게시하지 않고 이미 작성한 임시 부분 파일을 별도 보존한다. 취소와 원본 변경 오류도 유지한다.

## F25/F26 인수 범위

인수 등급은 **정답 검증**이다. 원본 바이트를 아는 불변 합성 NTFS 3.1 이미지(512B 섹터·4KiB 클러스터·1KiB 파일 기록)에서 아래 지원 사례를 확인했다. 실매체 시험, 다른 클러스터 크기·모든 기록 변형의 인수는 아니다.

| 항목 | 입력과 기대 결과 | 검증 근거 |
|---|---|---|
| F25 작은 파일과 외부 본문 | resident, 연속 외부 구간, 논리 EOF가 클러스터 중간인 파일의 정답 크기·SHA-256 일치 | `ntfs-image.test.mjs`, `ntfs-empty-nonresident.test.mjs` |
| F25 큰 파일의 논리 길이 | 9,437,321B 파일을 1MiB 이하 읽기로 저장, 물리 틈·할당 꼬리의 오염 바이트 제외 | `stage5-body.test.mjs` |
| F25 미초기화 꼬리 | 메타데이터가 선언한 미초기화 꼬리만 0으로 만들고 논리 크기 유지 | `stage5-body.test.mjs`, `ntfs-advanced.test.mjs` |
| F26 여러 구간과 확장 기록 | 네 물리 구간(LCN 3000→100→2200→1000), 두 파일 기록을 resident `$ATTRIBUTE_LIST`로 연결, 정답 해시 일치 | `stage5-body.test.mjs` |
| F26 잘못된 연결 거부 | 잘못된 소유자·세대·속성 ID·VCN 빈틈·물리 중복, 이후 확장 기록 변경을 거부 | `ntfs-attribute-list.test.mjs` |
| 오류·취소 | 첫 구간/두 번째 구간의 EIO·짧게 읽힘에서 완료 미게시, 이전에 저장한 바이트만 부분 파일로 보존; 취소·할당 충돌·확장 기록 변경 거부 | `stage5-body.test.mjs` |

지원 구현은 압축되지 않은 이름 없는 DATA와 resident 속성 목록을 포함한다. 속성 목록의 구현 한도는 64KiB·256항목, 확장 기록 64개이며 확장 기록마다 해당 DATA extent 하나를 해석한다. 이 상한의 모든 조합을 시험했다는 의미는 아니다. 비resident/중첩 속성 목록, 확장 기록에 분산된 sparse·compressed·ADS는 이번 인수 범위 밖이다. 일부 sparse·compressed 읽기의 기존 시험은 F27 전체 인수로 올리지 않는다.

## 이전 버전과 같은 이미지 비교

16MiB 이미지에 네 구간과 확장 기록으로 나뉜 9,437,321B 본문을 넣었다. 각 조각은 서로 다른 본문 패턴으로 순서 오류를 검출하며, 정상 초기화와 미초기화 꼬리 2,049B 변형에 대해 0.5.13과 0.5.14를 각각 실행했다.

| 결과 | 0.5.13 | 0.5.14 |
|---|---:|---:|
| 정답 크기·SHA-256 일치 | 2/2 | 2/2 |
| 검사 한도로 인한 부분 복구 오표시 | 2/2 | 0/2 |
| 삭제 전 원본과 같다고 앱이 자동 주장 | 0/2 | 0/2 |

이전 버전도 본문 자체는 정확히 읽었다. 이번에는 결과 판정을 고치고 큰 파일·실패 사례의 인수 근거를 확보했다. 실제 SSD에서 새 파일을 더 많이 찾았거나 복구율이 증가했다는 결과가 아니다. 문서 앱 열림·내용 렌더링 시험도 별도다.

입력 SHA-256:

- 정상 초기화: `1ac06f0fa4974c44a78396b277fe12baeebc6a39d23fabd0fb8d237874ce06ca`
- 미초기화 꼬리: `45528f971a7c61c88be2f2564c4869ff48d0bafd9ee413710238e41d0b413035`

정답 본문 SHA-256:

- 정상 초기화: `1531ef783fd9054d5ffe378711abc5e8d42c2820e5c8bd0ae5b208daa0da1563`
- 미초기화 꼬리: `f7ed204bba2137bf25061198e8489d5ac6036231932f747150a115a95ebf242b`

두 입력의 실행 전후 해시는 같다. 원본과의 비교는 시험 채점기가 별도로 수행하며 앱의 저장 후 다시 읽기 검증과 구별한다. 원시 결과·복구 파일은 `E:/RecoveryChat-Stage5-0514-20260926/comparison-final-v2/stage5-comparison.json`, 시험 로그·패키지·독립 검토는 같은 증거 폴더의 `acceptance.json`에 있다.

신규 본문 시험 13개를 포함한 전체 엔진 시험은 **550 통과·실패 0·기존 심볼릭 링크 생성 환경 제한 1개 제외**다. 전체 시험 후 조각별 패턴의 구별 여부를 강화했고 해당 본문 시험 13개와 같은 이미지 비교를 다시 통과했다. 개발 GUI의 결과 구분 시험 1개도 통과했다. GUI 시험은 검색 이벤트를 모사하며 실제 바이트 복구 시험과 별개다.

```powershell
node scripts/verify-stage5.mjs <baseline-engine-directory> <current-engine-directory> <fresh-output-directory>
```

## 남은 항목

필수 인수는 **19/54(35.2%)**, 5단계는 **F25/F26 지정 시험군 인수, F27~F30 미완료**다. 4단계는 보류 상태이며 F19~F24를 완료로 올리지 않았다.

실제 볼륨은 복사 전후 파일 기록·확장 기록·할당 상태를 확인하지만, 그 사이 물리 데이터만 바뀌는 모든 경합을 증명하지 못한다. 물리 구간 재읽기 비교 및 그 추가 I/O 효과는 F29에 남긴다. F30도 첫 실패 요청 구간 설명까지이며 전 구간 손상 지도·수리본 분리는 남았다. 잠금/암호화, 압축·희소·ADS의 전체 지원군, 외부 문서 앱 열림은 각각 F27/F28/F35의 별도 검증이다.
