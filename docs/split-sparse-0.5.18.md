# 0.5.18 — 여러 관리 기록에 나뉜 희소 본문 복구

5단계 F27의 일부 지원 확대다. 기존에 거절하던 분할 희소 DATA를 현재의 파일 소유 관계·구간·할당·기록 지문 검사로 연결한다. 새 검색 버튼 없이 기존 검색·미리보기·저장 경로에서 동작한다.

## 바뀐 동작

기본 기록에 들어 있는 resident `$ATTRIBUTE_LIST`가 같은 파일의 확장 기록들을 정확히 가리키면, 각 기록에 나뉜 희소 구간과 실제 본문을 논리 순서대로 읽는다. 빈 구간이 기록 경계를 가로지르거나 확장 기록 전체가 빈 구간인 경우에도 실제 본문의 위치가 앞당겨지지 않아야 한다.

0으로 채우는 곳은 메타데이터가 선언한 희소 구간과 미초기화 꼬리뿐이다. 물리 읽기 실패, 잘못된 소유자·세대·속성 번호, 구간 누락·중복, 다른 파일에 재할당된 구간과 변경된 확장 기록은 계속 거절한다. 저장은 논리 본문을 담은 일반 파일이며 원본의 희소 할당 속성 자체를 재생성하지 않는다. 출력 공간은 논리 파일 크기만큼 필요하다.

## 지원 범위

- 기본 기록: 이름 없는 비상주 DATA 하나, resident 속성 목록 하나. 일반 데이터 또는 압축하지 않은 희소 데이터.
- 희소 첫 헤더: unit 0의 64바이트 기본 헤더, 또는 unit 4의 72바이트 확장 헤더. 확장 헤더는 논리 용량과 실제 물리 용량을 각각 확인한다.
- 후속 기록: unit 0, 이름 없는 DATA 조각 하나, 기본 기록용 크기 필드는 0. 모든 조각의 희소 표시가 일치해야 한다.
- 기존 상한 유지: 속성 목록 64KiB·256항목, 확장 기록 64개, 데이터 구간 총 65,536개.
- 분할 압축·다른 희소 헤더 변형·비상주/중첩 속성 목록·복잡한 확장 기록·일반 ADS 확대는 미지원이다.

속성 목록이 있는 파일은 **다른 검색에서 확보한 본문 연결**을 비활성화한다. 기존 연결 키가 기본 기록만 확인하므로 확장 기록 전체의 동일성까지 증명하지 못하기 때문이다. 일반 분할 파일에도 같은 제한을 적용하며, 현재 검색에서의 본문 확보·미리보기·저장은 기존 확장 기록 검사로 처리한다.

형식 근거: [Microsoft 속성 목록 구조](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-list-entry), [희소 파일 읽기 동작](https://learn.microsoft.com/en-us/windows/win32/fileio/sparse-files). 외부 구현 코드를 가져오거나 의존성을 추가하지 않았다.

## 검증과 남은 범위

시험 입력은 정답 바이트를 따로 가진 고정 합성 NTFS 이미지다. 일반/확장 첫 헤더, 빈 후속 기록, 여러 확장 기록과 미초기화 꼬리를 구·신 버전에 같은 입력으로 제공한다. 오류·기록 변경·할당 변경·취소 시험 및 실제 앱 작업자 저장 경로를 별도로 확인한다.

최종 시험 수, 비교 결과, 배포본·ZIP 대조와 독립 검토는 `E:/RecoveryChat-SplitSparse-0518-20260927/acceptance.json`에 보존한다. 실제 SSD 삭제 파일 시험이나 복구율 측정은 포함하지 않는다. F27은 아직 부분 구현·미인수이며 필수 체크리스트 **19/54(35.2%)**를 유지한다.
