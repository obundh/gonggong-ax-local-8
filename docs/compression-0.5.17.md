# 0.5.17 — NTFS 압축 본문 크기 해석 보강

5단계 F27의 일부 보강이다. NTFS가 압축해 저장한 파일의 본문을 다루며 ZIP/PDF 자체의 압축을 추가 지원하는 변경은 아니다. F27 전체 인수, 실제 SSD 삭제 복구율 상승, 외부 문서 앱의 정상 열림을 뜻하지 않는다.

## 수정한 결함

이전 엔진은 압축 속성의 논리 할당 크기와 실제 물리 저장 크기를 같다고 요구했다. 예를 들어 64KiB 논리 단위를 4KiB에 압축한 정상 구조도 거절했다. 기존 합성 시험 생성기도 두 필드를 모두 4KiB로 만들어 같은 오류를 놓쳤다. 엔진과 시험 생성기를 함께 바로잡고, 구버전과 신버전에 동일한 새 입력을 제공해 비교한다. 과거에 저장한 시험 이미지와 결과는 덮어쓰지 않는다.

또한 압축을 해제한 길이가 초기화된 본문 길이와 반드시 같아야 한다고 요구했다. 압축 단위가 파일 끝이나 초기화된 범위를 넘어서는 경우에도 필요한 본문만 복사하고, 메타데이터가 선언한 미초기화 꼬리만 0으로 채우도록 수정했다. 압축 해제 데이터가 필요한 본문보다 짧거나 손상된 경우, 물리 읽기에 실패한 경우에는 완료본을 게시하지 않는다.

## 지원 범위와 근거

- NTFS 3.0/3.1, 4KiB 클러스터, 16클러스터(64KiB) 단위의 LZNT1, 기본 기록에 담긴 단일 이름 없는 DATA를 대상으로 한다.
- 논리 할당 크기는 VCN 전체 용량, 확장 헤더의 실제 할당 크기는 물리 구간 합계와 각각 일치해야 한다. 저장 길이는 논리 파일 길이를 따른다.
- 완전 물리 단위는 원시 본문, 완전 희소 단위는 메타데이터상 0으로 다룬다. 압축 단위의 잘못된 배치·할당 중복·부족한 데이터·크기 불일치·출력 한도 위반은 계속 거절한다.
- 압축 해제는 기존 자체 LZNT1 구현을 사용한다. Windows `RtlCompressBuffer`로 만든 바이트는 독립 시험 입력이며 제품 의존성을 추가하지 않는다.
- 분할 압축·희소 스트림과 일반 ADS 확대, 다른 클러스터 크기, 잠긴 암호화 파일, 실제 매체의 모든 변경 경합은 이번 범위 밖이다.

형식 근거: [Microsoft ATTRIBUTE_RECORD_HEADER](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-record-header), [NTFS3 속성 구조](https://github.com/torvalds/linux/blob/master/fs/ntfs3/ntfs.h). 구조를 대조했으며 외부 드라이버 코드를 제품에 복사하지 않았다.

## 검증 기록

새 압축 회귀시험, 동일 입력의 구·신 버전 비교, 전체 엔진 시험, 최종 패키지 화면과 소스 대조 결과는 `E:/RecoveryChat-Compression-0517-20260927/acceptance.json`에 기록한다. 합성 NTFS 구조와 실제 Windows 압축 바이트를 조합한 시험이며 실제 SSD 삭제 시험과 구분한다.

필수 체크리스트는 **19/54(35.2%)**, F27은 **부분 구현·미인수**를 유지한다. 이 비율은 기능별 인수 진행률이며 파일 복구율이 아니다.
