> **개발 이력 문서입니다.** 아래 수치·미지원 상태·실행 경로는 작성 당시 기록이며 최신 상태가 아닐 수 있습니다. 현재 상태는 [공개 현황](../../docs/STATUS.md)을 따릅니다. 기존 구현표 103/103과 현재 필수 인수 21/54는 서로 다른 기준입니다. 로컬 원자료 전체는 공개하지 않습니다.

# 공공 AX 로컬 시리즈 8 - 파일 복구

0.6.1은 변경되지 않은 디스크 이미지의 정밀 검색을 중단 지점부터 이어갑니다. 이전 추출 파일을 다시 검증하며, 실제 드라이브 검색 재개와 SSD 복구율 개선은 이번 인수 범위가 아닙니다. [범위와 검증](docs/deep-resume-0.6.1.md).

0.6.0은 최근 문서 바로가기에서 이름·경로 단서를 찾고, 10단계 체크리스트의 인수·보류·재개 조건을 정리합니다. 경로 단서에는 파일 본문이 없으며 대상 존재·삭제 여부를 확인하지 않습니다. 필수 인수 21/54는 복구율이 아닙니다. [현재 범위와 증거](docs/ten-stage-closeout-0.6.0.md).

0.5.20은 Office 기본 자동 복구 위치 4곳을 한 번에 확인하고, 남아 있는 문서·임시 사본의 출처와 수정 시각을 보여줍니다. 선택한 사본을 별도 위치에 저장하며 원본·최신 버전 여부는 미확인으로 표시합니다. [지원 범위와 검증](docs/autosave-0.5.20.md).

Windows용 파일 복구 앱 0.6.1입니다. 상단에서 **직접 찾기 / 질문으로 찾기**를 선택합니다. 첫 화면에서 위치·기간·선택적인 이름을 고른 뒤 검색합니다. 검색한 파일의 정렬·미리보기·저장은 결과에 나타나며, 상세 단계와 기술 정보는 필요할 때 펼칩니다. 생성형 AI 채팅은 사용하지 않습니다.

`도구 · 안내 → 원본 보관 · 이미지`에서 선택한 볼륨 또는 raw 이미지를 별도 보관하고 전체 해시·수집 기록을 확인한 뒤 재검색할 수 있습니다. 고정 이미지 시험은 통과했으며 실제 장치별 전체 인수는 남아 있습니다. [2단계 변경과 검증 범위](docs/stage2-0.5.0.md)를 참고하세요.

검색 경고의 건수와 파일 후보의 개수는 다릅니다. 결과 목록에서 경고 전체를 펼쳐볼 수 있으며, 삭제 이력이 검색 중 바뀌어 검증을 마치지 못한 경우에는 파일이 없다고 확정하지 않고 실패 이유와 다시 검색할 방법을 표시합니다.

휴지통에서도 삭제된 파일은 남아 있는 기록과 본문을 읽어 새 파일로 저장합니다. 0.3.4부터 지원 범위의 다운로드 출처 정보(`Zone.Identifier`)도 함께 보존합니다. 삭제 기록 발견, 미리보기, 본문 저장은 각각 다른 단계이며 저장 완료만으로 삭제 전 원본과 같다고 보장하지 않습니다. 지원 조건은 `SUPPORT.md`를 참고하세요.

0.5.14는 5단계 본문 복구 검증을 보강합니다. 8MB 검사 한도를 넘는 전체 저장 파일을 부분 복구로 표시하던 문제를 고쳤고, 읽기 실패 요청 구간을 설명합니다. 조각난 9MB 파일의 정확한 복구를 고정 이미지로 검증했습니다. [5단계 지원 범위와 인수](docs/stage5-0.5.14.md).

0.5.15는 같은 검색 안에서 중복하던 장치 조회를 줄이고, 8MB를 넘는 파일에서도 확장자와 실제 형식의 불일치를 표시합니다. 연결 준비 시험의 첫 본문 확보 중앙값은 4.25초에서 2.25초로 줄었습니다. 실제 SSD 복구율 향상을 뜻하지 않습니다. [변경과 검증 범위](docs/hardening-0.5.15.md).

## 0.5.16 이전 확보본 다시 보기·저장

같은 앱 세션의 앞선 검색에서 정상 미리보기 본문을 확보했고 동일한 장치·삭제 사건·파일 기록·저장 구간을 확인한 경우에만 **이전 확보본 보기 / 이전 확보본 저장** 버튼이 나타납니다. 현재 결과는 그대로 남기며, 선택한 이전 본문은 저장 시각과 출처를 표시하고 다시 해시 검사합니다. 최근 유지 작업 최대 3개 안에서만 연결하며 앱 재시작 후 자동 연결은 지원하지 않습니다. 실제 SSD 복구율 개선을 측정한 변경은 아닙니다. [범위와 검증](docs/capture-carry-0.5.16.md).

## 0.5.17 압축 파일 본문 읽기

NTFS 압축 파일의 논리 용량과 실제 압축 저장 용량을 혼동해 정상 구조를 거절하던 문제를 고쳤습니다. 압축 해제 후 파일 끝과 초기화된 본문 길이를 지키며, 부족하거나 읽지 못한 데이터는 정상 복구로 처리하지 않습니다. 실제 SSD 복구율 재측정은 포함하지 않습니다. [지원 범위와 검증](docs/compression-0.5.17.md).

## 0.5.18 분할 희소 파일 본문 읽기

여러 관리 기록에 나뉜 희소 파일도 같은 파일임을 검증한 뒤 기존 검색·미리보기·저장 흐름에서 처리합니다. 기록된 빈 구간과 실제 읽기 실패를 구분하며, 잘못된 연결이나 변경된 기록은 거절합니다. [지원 범위와 검증](docs/split-sparse-0.5.18.md).

속성 목록으로 연결된 파일은 현재 검색에서 복구할 수 있지만, 확장 기록까지 비교하는 연결 키가 준비되기 전에는 다른 검색의 이전 확보본을 연결하지 않습니다.

## 0.5.19 손상 문서의 부분 텍스트 보존

뒤쪽 ZIP 항목이나 일부 XML이 손상돼도 검증된 다른 텍스트는 별도 파일로 남깁니다. 빠진 부분과 미검사 범위를 표시하며 전체 문서 복구로 세지 않습니다. [지원 범위와 검증](docs/partial-zip-salvage-0.5.19.md).

## 실행

개발 폴더의 `실행.cmd`를 실행하세요. 이 PC에서는 C: 검색의 작업 공간을 분리하기 위해 `E:/RecoveryChat-0.6.1/win-unpacked/공공 AX 로컬 시리즈 8 - 파일 복구.exe`를 우선 실행합니다. 새 버전은 별도 폴더에 제공합니다.

다른 PC에서는 빌드한 `win-unpacked` 폴더 전체를 **원본과 다른 디스크에 복사**하고 안의 EXE를 실행합니다. 이번 로컬 패키지는 `E:/RecoveryChat-0.6.1/win-unpacked/`에 있습니다. EXE 한 개만 옮기면 안 됩니다. Node.js 설치는 필요하지 않습니다.

실제 드라이브를 읽을 때 Windows 허용을 한 번 받으면 앱을 닫을 때까지 같은 읽기 전용 도우미를 재사용합니다. 검색 재시작·다른 드라이브 선택마다 다시 허용할 필요는 없습니다. 앱 재실행 또는 도우미 연결 종료 후 재연결에는 다시 허용이 필요합니다.

삭제 목록은 복구본 저장 폴더를 고르기 전에 확인할 수 있으며 후보 기록은 작업 공간에 보관합니다. 실제 원시 장치에서 파일을 저장하거나 정밀 검색할 때 프로그램 작업 공간과 출력 폴더 모두 원본과 다른 물리 디스크에 있어야 합니다. C:와 D:가 같은 디스크이면 분리한 것으로 보지 않습니다. 프로그램 기본 작업 공간은 EXE 옆 `recovery-workspace`입니다. 필요하면 실행 전에 `RECOVERY_WORKSPACE` 환경변수로 다른 디스크의 폴더를 지정합니다.

0.5.11은 파일 기록 없이 남은 HWP 5 본문을 정밀 검색에서 추출합니다. 연속된 CFB v3 영역만 지원하며 생성한 이름으로 표시합니다. 원래 이름·문서 정상 열림은 별도 확인이 필요합니다. [지원 범위](docs/stage6-0.5.11.md).

0.5.13은 빈 기록 검색에서 최신 삭제 후보를 먼저 확보하고 전체 빈 기록 탐색을 이어갑니다. 고정 이미지에서 최신 파일의 한도 누락을 보완했으며 실제 SSD 복구율 향상은 아직 재측정하지 않았습니다. [범위와 비교](docs/stage4-0.5.13.md).

0.5.12는 정밀 검색에서 실제로 검사를 마친 양과 미검사 범위를 구분합니다. 찾는 방법의 검색량 선택으로 1GB·4GB 제한 검색도 가능하며 추출 저장량도 제한합니다. 새 검색은 처음부터 시작합니다. [검사 범위와 제한](docs/stage6-0.5.12.md).

## 사용

**후보 선택 → 복구해서 저장 → 폴더 선택 → 복구본 확인** 순서입니다. 복구본의 전체 바이트를 다시 읽어 저장 중 계산한 크기·SHA-256과 대조합니다. 결과 카드에서 본문 저장 확인, 문서 미리보기 확인, 이름 복원 여부를 각각 표시하며 **복구본 미리보기 / 파일 위치 열기**로 확인할 수 있습니다.

Windows NTFS의 같은 파일 세대에서 이름 변경 전·후 기록과 삭제 기록이 명확하게 연결될 때 `$R…` 대신 휴지통 이동 직전 이름으로 저장합니다. 0.5.6에서는 여러 번 이름을 바꿨거나 휴지통에서 꺼냈다가 다시 버렸어도 이름과 부모 폴더 이력이 연속되면 연결합니다. 이력이 끊기거나 세대·부모·하드링크 정보가 충돌하면 발견한 이름을 유지합니다. 파일명 복원은 본문 동일성 증명이 아닙니다. 파일마다 별도 결과 폴더에 저장해 기존 결과를 덮어쓰지 않습니다.

0.5.7은 실제 Windows NTFS 검색에서 발견한 삭제된 `$I` 정보 파일을 제한적으로 해석합니다. 원래 이름·경로·기록된 크기·휴지통 이동 시각은 **휴지통 정보 단서**로 표시하며, 본문과의 연결을 확정하거나 저장 버튼을 켜지 않습니다. 휴지통 이동 시각은 영구 삭제 시각이 아닙니다. 이미지 검색 경로는 아직 이 추가 해석을 사용하지 않습니다. [변경과 검증 범위](docs/stage4-0.5.7.md).

0.5.8은 발견된 기록이 가리키는 현재 폴더의 인덱스에서 옛 이름 흔적도 제한적으로 확인합니다. **폴더 기록 흔적**은 삭제 여부·본문 위치가 미확정인 별도 단서입니다. 수정 시각을 삭제 시각으로 사용하거나 기존 복구 후보와 합치지 않습니다. 이 추가 경로도 실제 Windows NTFS 검색에만 연결했으며, 이미지 검색 경로는 기존 방식입니다. [범위와 검증](docs/stage4-0.5.8.md).

0.5.10은 두 폴더 탐색에 각각 최대 128개 단서를 배정해 앞선 탐색이 가득 찼을 때 추가 탐색을 건너뛰던 문제를 고칩니다. 전체 후보 보관 한도와 기존 읽기·시간·본문 검증 조건은 유지합니다. [범위와 검증](docs/stage4-0.5.10.md).

0.5.9는 사용 해제된 폴더 인덱스 블록의 옛 항목과 남는 영역까지 추가 확인합니다. 기존 경로를 먼저 마친 뒤 별도 읽기·시간 한도로 진행하며, 같은 파일 참조·세대·이름·부모의 중복 단서는 추가하지 않습니다. 삭제 사실과 본문 위치는 여전히 미확정입니다. [범위와 검증](docs/stage4-0.5.9.md).

문서 검사는 최대 8MiB의 지원 형식에서 제한적인 텍스트·이미지 미리보기를 확인합니다. 암호, 형식 불일치·손상 가능성, 미지원·크기 한도는 구별해 표시합니다. 더 큰 파일도 바이트 저장 확인은 수행합니다. 전체 페이지·서식과 외부 문서 프로그램에서의 열림 여부, 삭제 전 내용의 동일성은 보장하지 않습니다. 덮어써지거나 TRIM으로 사라진 본문을 생성해 채우지 않습니다.

프로그램 모드는 **삭제 기록 찾기 → 정밀 검색** 두 단계입니다. 휴지통을 비웠거나 완전 삭제한 파일의 기록을 기본으로 찾습니다. 기간은 전체·오늘·7일·30일 또는 시작일/종료일로 지정하며 시각 미확인 후보도 기본 포함합니다. 삭제 시각이 없으면 수정일을 대신 사용하지 않습니다.

**실제 Windows NTFS 장치는 전체 기간에서도** Windows의 삭제·이름 변경 이력을 먼저 읽고 연결된 파일 기록만 확인합니다. 기간을 지정하면 그 기간과 관련된 기록으로 범위를 좁힙니다. 채팅에서도 **기간을 정해서 빠르게 찾기**로 검색 전에 날짜를 정할 수 있습니다. 이미지 파일과 다른 파일시스템은 기존 지원 경로를 유지합니다.

빠른 검색은 남아 있는 지원 변경 기록 범위에 한정됩니다. 이력이 없거나 일부만 읽어도 자동으로 느린 검색을 시작하지 않습니다. Windows NTFS 검색 결과의 **빈 기록 추가 탐색**을 누르면 현재 사용하지 않는 파일 관리 기록 자리를 선별해 추가 후보를 찾습니다. 삭제 시각 미확인 후보도 포함합니다. 이미지의 기간 검색에는 기존 **전체 기록 검색 · 더 오래 걸려요** 버튼을 유지합니다. 날짜 입력만 바꾸면 현재 목록 안에서 필터링하며, 새 범위를 읽으려면 **선택 기간으로 다시 검색**을 누릅니다.

새 탐색 경로의 후보는 **선택 시 확인** 상태로 표시합니다. 발견만으로 내용을 읽을 수 있다고 확정하지 않습니다. 미리보기와 매 저장 시점에 기록 세대·지문·할당 정보를 다시 확인하며, 바뀐 기록은 저장하지 않습니다. 원래 이름이 이름 변경 이력에 남아 있으면 **이전 이름 이력**으로 표시하고, 현재 이름과 구별합니다.

파일 이름 비교는 문자 일치·일부 일치·유사·원래 이름 미확인·불일치로 구분합니다. 이름이 일치하지 않아도 삭제 후보를 유지하고, 이름이 바뀌거나 사라졌을 가능성과 다른 정보 확인 방법을 안내합니다. 이름 일치는 원본 내용의 동일성을 뜻하지 않습니다.

목록을 한 번 누르면 오른쪽에 기본 정보와 가능한 미리보기가 나타납니다. 텍스트·제한적인 PDF 텍스트·지원 Office/HWP 내용·이미지를 최대 8MiB까지 메모리에서 확인하며, 저장 폴더를 미리 묻거나 임시 복구본을 쓰지 않습니다. PDF의 원래 배치를 재현하지는 않습니다. 검색 중 선택한 파일은 기본 정보를 먼저 표시하고 작업 종료 후 미리보기를 불러옵니다. 좁은 창에서는 미리보기가 목록 아래에 배치됩니다.

대화 진행, 검색·일시정지·중단 처리, 미리보기·저장, 파일 선택 창이 열린 동안은 모드를 바꿀 수 없습니다. 채팅은 작업 종료 후에도 **대화 끝내기**로 종료한 뒤 전환합니다. 찾은 결과는 유지합니다. 프로그램 모드의 도구 메뉴에서는 자동 저장본과 이전 작업도 대화 없이 선택합니다.

앱은 현재 휴지통에 있는 항목을 목록으로 가져오지 않습니다. 휴지통에서 이미 삭제된 정보 파일은 NTFS 삭제 기록 검색 중 단서로 해석할 수 있습니다. 상단 **휴지통 열기**를 누르면 Windows 휴지통이 열립니다. 채팅에서는 휴지통 확인 여부를 짧게 안내하고, 비움·완전 삭제·휴지통에도 없음에 따라 삭제 기록 찾기로 이어집니다.

삭제 시각이 확인된 파일은 최신순으로, 확인되지 않은 파일은 별도로 표시합니다. 다른 드라이브는 **다음 위치 찾기**로 이어갑니다. 이전 버전의 휴지통 검색 기록은 보존하지만 앱에서 다시 검색하지 않습니다.

말풍선은 가볍게 떠오르며 나타나고, 장치 확인·검색·저장 중에는 움직이는 표시와 현재 작업명이 나타납니다. Windows 모션 감소 설정을 따릅니다.

1. 직접 삭제했는지, 찾아보니 사라졌는지 고릅니다. 상황에 맞춰 휴지통 확인 여부를 묻습니다.
2. 드라이브·폴더·이미지를 고르고 기억나는 파일명이나 종류만 입력합니다.
3. 삭제 파일 찾기, 복사본·비슷한 파일 찾기, 깊게 찾아보기 중 필요한 작업을 선택합니다.
4. 프로그램 모드는 후보를 25개씩, 채팅 모드는 5개씩 불러옵니다. 필터·정렬로 좁히고 파일을 눌러 미리 봅니다. 같은 조건의 다음 페이지는 계산 결과를 재사용하며, 검색 중 새 후보나 변경이 생기면 다시 계산합니다. 기간·이름 등 조건을 처음 적용할 때는 후보 전체 계산 시간이 필요합니다.
5. 검색이 끝나거나 중단된 뒤 파일을 더블클릭하거나 저장 버튼을 누르고, 저장 폴더를 선택해 파일별 결과를 확인합니다. 정밀 검색은 파일을 추출하면서 진행하므로 시작 전에 별도 저장 위치를 고릅니다.

글자·화면 확대는 Ctrl + +, 축소는 Ctrl + -, 원래 크기는 Ctrl + 0을 사용합니다.

도구 메뉴에서 자동 저장본, 이전 작업 기록, 파일명 인덱스, 후보끼리 내용 비교, 제한적 손상 문서 추출·PNG 재구성을 사용할 수 있습니다. 이전 작업은 원본을 재확인하며, NTFS 이미지는 검증된 저장 지점부터 이어갑니다. 다른 검색은 처음부터 재검색하고 기존 복구본을 유지합니다.

## 선택형 파일명 AI 팩

기본 앱은 AI가 없어도 동작합니다. 별도 `RecoveryChat-AI-Pack.zip`을 앱 폴더에 풀면 `optional-ai`와 `models/name-embedding` 폴더가 생깁니다. 도구 → 파일명 의미 검색을 누를 때만 로컬 모델을 검증·실행합니다. 비교가 끝나면 모델을 해제합니다. 이름 없는 카빙 결과는 의미 검색에 사용하지 않습니다.

모델은 약 150MB, 선택형 런타임은 약 26MB입니다. 정확한 버전·라이선스·구성·실측은 `models/README.md`, `optional-ai/models/README.md`와 동봉 고지를 참고합니다. 앱에서 다운로드나 문서 업로드를 자동 수행하지 않습니다.

## 지원과 검증

자세한 지원 구조·파일별 한계는 `SUPPORT.md`, 기능별 진행률은 `BUILD_CHECKLIST.md`, 개발·검토 근거는 `DEVELOPMENT_LOG.md`에 있습니다. 지원 기능 구현과 모든 실제 장치에서의 복구 성공을 같은 뜻으로 쓰지 않습니다.

자동 시험은 합성 NTFS/FAT/exFAT·MBR/GPT 이미지, 카빙·문서 미리보기·부분 추출, 선택 저장·물리 장치 경계, 실제 Electron 화면 흐름을 사용합니다. 사용자 파일 삭제나 포맷을 자동 시험에 포함하지 않습니다. 별도 승인한 더미 파일 실험에서는 휴지통에서도 삭제한 3개 기록을 발견했지만 당시 본문 복구는 미지원 ADS 때문에 실행되지 않았습니다. 바탕화면에 돌려놓은 파일은 안전 복사본이며 복구 성공으로 집계하지 않습니다. 이번 기능의 합성 시험과 실제 SSD에서의 내용 복구 성공은 구별합니다.

```powershell
npm run test:engine
npm run test:desktop
npm run demo:engine
npm run build:win
node scripts/progress.mjs --write
```

브라우저 `node serve.mjs`는 UI를 제공할 뿐 실제 장치 브리지는 없습니다. `?demo=1`은 안내만 보는 모드이며 가상 파일을 실결과처럼 만들지 않습니다. 기본 포트는 54137입니다.

앱은 Electron 44.3.0을 사용합니다. UI는 assistant-ui Stockbroker 디자인을 참고한 자체 구현이며 외부 Stockbroker 서버나 assistant-ui 런타임을 연결하지 않았습니다. 배포 라이선스 고지는 `THIRD_PARTY_NOTICES.md`와 EXE 옆 Electron/Chromium 고지에 포함됩니다.
