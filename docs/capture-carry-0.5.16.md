# 0.5.16 이전 검색에서 확보한 본문 활용

앞선 검색에서 정상 미리보기 본문을 확보했어도 이후 검색이 손상된 본문을 읽으면, 기존 화면에서는 현재 작업의 본문만 선택할 수 있었다. 같은 파일 기록이라는 근거를 확인한 경우 별도의 **이전 확보본 보기 / 이전 확보본 저장** 버튼으로 앞서 확보한 본문을 사용할 수 있다.

## 연결과 저장 조건

- 같은 앱 세션의 최근 유지 작업 최대 3개 안에서 이전 작업을 찾는다. 다른 세션의 저장 폴더를 자동 탐색하거나 재시작 후 연결하지 않는다.
- 선택 장치의 식별자·물리 디스크·읽기 계층과 실제 열린 리더의 식별자가 두 작업에서 일치해야 한다. 동작 시 장치 목록을 다시 확인한다. 필요한 식별 근거가 없거나 작업자가 종료되면 이전 확보본을 연결하지 않는다.
- 삭제 사건의 파일 참조·USN, 파티션, MFT 번호·세대·원시 기록 해시, 데이터 구간 해시, 크기가 모두 같아야 한다. 이름이나 목록 ID만으로 연결하지 않는다. 삭제 사건이 없거나 여러 개여서 불명확하면 연결하지 않는다.
- 앞선 본문은 확보 당시 지원 미리보기가 가능해야 한다. 현재 확보본과 SHA-256이 같으면 중복 버튼을 표시하지 않는다.
- 미리보기와 저장은 앞선 작업자가 소유한 확보본만 읽는다. 확보 당시 파일 식별 정보·크기·SHA-256 및 보존한 보조 스트림을 다시 확인하며, 없거나 달라졌으면 실패한다. 현재 원본을 다시 읽어 대신 제공하지 않는다.
- 현재 검색 결과와 기본 복구 동작은 유지한다. 이전 본문 저장은 별도 출처와 확보 시각, 요청한 검색 작업을 결과에 남긴다. 삭제 전 원본과 동일하다는 판정은 하지 않는다. 실패 후 재시도·저장 위치 변경도 같은 이전 확보본을 대상으로 하며, 결과 폴더·목록 내보내기는 실제 저장 작업에 연결한다.

## 범위와 제한

F29 일부 보강이다. 본문을 확보하기 전 덮어쓰기·TRIM으로 사라진 데이터, 실제 매체의 읽기 도중 경합, 재시작 후 과거 본문 연결은 해결하지 않았다. 이름·MFT·삭제 근거가 바뀌었지만 같은 문서일 가능성이 있는 경우에도 자동 연결하지 않는다. 이 변경의 시험은 합성 NTFS 입력과 실제 작업자·Electron UI를 이용하며 새 SSD 복구율을 주장하지 않는다. 필수 체크리스트 19/54(35.2%) 유지.

## 확인한 결과

- 전체 엔진 582개 통과·실패 0·기존 Windows 심볼릭 링크 권한 제한 1개 제외.
- 새 연결 키·서비스·실제 작업자 시험 13개가 포함된다. 합성 NTFS의 비상주 PNG를 먼저 확보한 뒤 MFT와 할당 정보를 유지한 채 본문만 바꿨다. 기본 저장은 현재 손상 본문이며, 명시적으로 선택한 이전 확보본만 정답 SHA-256과 일치했다. 이전 확보본 보기·저장에는 추가 원본 볼륨 읽기가 없었다.
- 보관 파일 변조, 잘못된 연결 증거, MFT 세대 변경, 다른 장치/읽기 계층, 만료 작업, 동시 요청과 취소를 확인했다. UI는 두 모드의 버튼과 출처 표시, 저장 폴더 취소, 이전 작업으로의 중단·재개 요청을 시험했다.
- 기존 후보 비교 시험 4개에서 삭제 사건이 없는 후보에 불필요한 빈 필드가 추가된 차이를 발견했다. 근거가 있을 때만 필드를 추가하도록 수정한 뒤 전체 시험을 통과했다.

독립 검토에서 재시도 시 현재 본문으로 대상이 바뀌는 문제와 결과 버튼의 작업 연결 오류를 찾았다. 재시도 대상 및 결과 소유 작업을 유지하도록 수정하고, 두 재시도 버튼과 결과 폴더·내보내기·도구 메뉴의 IPC 대상을 GUI 회귀 시험으로 확인했다.
