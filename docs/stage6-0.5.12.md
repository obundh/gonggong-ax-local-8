# 0.5.12 — 정밀 검색 범위와 제한 종료

정밀 검색에서 1MiB 버퍼를 읽었더라도 첫 후보에서 개수 한도에 도달하면 버퍼 끝까지 후보 검사를 마친 것이 아니다. 이 버전은 읽은 양과 검사를 마친 양을 따로 기록하고, 남은 영역을 파일이 없는 영역으로 오인하지 않게 표시한다.

## 동작

- 기존 전체 검색을 기본으로 유지한다. 직접 찾기의 `찾는 방법과 보호 점검 → 정밀 검색량`에서 1GB/4GB 제한 검색을 선택할 수 있다. 표시 단위 GB는 1024³바이트다.
- 1GB 검색은 추출 파일 쓰기 256MB, 4GB 검색은 1GB를 함께 제한한다. 한 파일이 남은 추출 한도를 초과하면 그 파일을 쓰기 전에 제한 종료한다. 이미 쓴 임시·부분 파일도 쓰기 예산에 포함한다.
- 검색량 제한은 시작 표식을 찾는 순차 검사 읽기에 적용한다. 이미 발견한 파일의 구조 검증·추출은 같은 선택 구간 안에서 추가로 읽을 수 있다. 따라서 전체 물리 읽기량·소요 시간·작업 폴더 전체 디스크 사용량의 상한은 아니다. 추출 파일당 기존 64MiB 및 형식별 제한도 유지한다.
- 낮은 위치부터 확인하므로 제한 검색이 최근 파일이나 원하는 파일의 위치를 먼저 확인한다는 뜻은 아니다. 날짜·이름·정답 위치로 영역을 몰래 좁히지 않는다.
- 검색량·추출량·후보 개수 제한, 읽기 오류, 사용자 취소, 원본 변경과 일반 오류를 구분한다. 제한 종료는 전체 완료로 표시하지 않는다.
- 새 정밀 검색은 처음부터 시작한다. 현재 실행 중인 작업의 일시 정지·이어하기는 기존대로 사용할 수 있지만 취소·앱 종료 후 정밀 검색 체크포인트 재개는 추가하지 않았다.

## 범위 기록

작업의 `coverage`에는 선택한 바이트, 시작 표식 검색에서 실제 읽은 바이트, 후보 검사를 마친 바이트, 미검사 바이트, 읽기 오류 바이트, 추출 파일에 쓴 바이트와 종료 사유가 남는다. 외부에 반환·저장하는 검사·오류 구간 목록은 각각 1,024개로 제한하고 생략 여부를 표시한다. 내부 집계는 전체 구간을 유지하여 합계는 정확히 남긴다. 이 기록은 원본 파일의 복구 성공률이 아니다.

읽기 오류가 난 구간은 검사 완료 바이트에 넣지 않는다. 청크 경계에서 다음 바이트가 필요한 부분도 보수적으로 미검사로 남긴다. 같은 구간을 겹쳐 읽는 검증·추출 바이트는 검사 진척에 중복 합산하지 않는다. 취소·원본 변경 뒤에도 확인한 범위와 중단 사유를 가능한 작업 기록에 보존한다.

원시 볼륨에서 미할당 지도는 그때 관측한 지도다. 실행 중인 Windows가 바꾸는 파일 할당을 동결한 것이 아니며, 포렌식 이미지의 불변성과 같지 않다.

## 검증과 남은 범위

검증 기록은 `E:/RecoveryChat-DeepCoverage-0512-20260926/`에 보존한다. 후보 한도 중간 종료, 청크 경계, 서로 떨어진 범위, 읽기 오류, 취소, 출력 예산, 실제 작업자·화면 연동을 시험한다. 고정 이미지의 바이트 범위 검증과 실제 SSD의 파일 복구율을 구분한다.

이번 C: 실매체 사전 연결은 `HELPER_TIMEOUT`으로 끝났다. `E:/RecoveryChat-RecoveryRate-0511-20260926/`에 실패 기록을 보존했고 시험용 파일 생성·삭제는 0개다. 같은 내용의 반복 삭제 시험은 과거 회차 잔존 사본과 혼동할 수 있으므로, 다음 실측에서 삭제 전 저장 구간을 검색에 제공하지 않는 별도 정답 자료로 봉인하고 검색 후보를 고정한 뒤 사후 대조해야 한다.

F31 일부 보강이며 필수 인수 **17/54(31.5%) 유지**. 정밀 검색 재시작 체크포인트, 전체 선택 범위 실매체 인수, 원본 상태 동결과 다른 프로그램 비교는 남아 있다.
