# 0.6.1 — 이미지 정밀 검색 이어서 검사

작성일: 2026-09-27. 6단계 F31 일부 보강. 필수 인수 **21/54 (38.9%)** 유지.

## 달라진 동작

변경되지 않은 디스크 이미지에서 정밀 검색이 취소되거나 검색량·추출량 한도에 닿은 경우, `도구 · 안내 → 이전 작업 기록`에서 해당 검색을 골라 시작하면 저장된 위치부터 이어간다. 새 결과 폴더를 만들고 이전 추출본을 검증해서 함께 보여준다. 실제 드라이브에는 이 재시작 경로를 적용하지 않는다.

이미지의 파일 식별자·크기·수정 및 변경 시각, 선택한 검색 범위·파일별 제한을 대조한다. 이전 추출본은 허용된 출력 폴더 안의 일반 파일인지, 파일 식별 정보·크기·SHA-256이 같은지 검사한다. 변경·누락·설정 불일치가 있으면 이어서 검사를 거부하고 새 검색을 안내한다. 원본 이미지 전체를 매번 해시하는 방식은 아니며, 악의적인 관리자에 대한 원본 무결성 보증은 아니다.

서명이 구간 경계에 걸리면 최대 7바이트를 다시 읽는다. 출력 한도로 저장하지 못한 파일, 추출 도중 취소된 파일은 해당 위치에서 다시 시도한다. 이미 발행한 후보의 저장 범위를 기억해 중복과 내부 표식의 재발행을 막는다. 기존 결과는 이전 출력 폴더에 남으므로 해당 폴더도 보존해야 한다.

검사·출력 바이트와 오류는 이전 작업을 포함해 누적한다. 검색량·추출량 예산은 이번 실행에 새로 적용한다. 후보 한도 10,000개는 누적 한도이며 이어서 검사로 우회하지 않는다. 읽기 오류·부분 파일·지원하지 않는 구조는 재시작 후에도 미완료 사유로 유지한다. 앱의 범위 표시가 생략하는 1,024개 초과 구간도 내부 재시작 기록에는 모두 보존한다.

체크포인트는 시작·정상 종료·취소 및 검색 중 약 5초 간격으로 저장한다. 강제 종료 시 마지막으로 디스크에 저장된 지점 뒤의 작업은 다시 읽을 수 있다. 체크포인트 최대 16MiB, 허용 출력 루트 최대 128개다. 한도를 넘으면 추출 파일은 유지하며 검색 오류 또는 이전 작업 기록의 재개 불가 사유로 알린다. 새 체크포인트를 저장하지 못한 경우 이전 작업의 저장 기록을 사용할 수 있다.

## 고정 자료 전후 비교

256MiB 고정 이미지에 경계 PDF를 포함한 합성 파일 5개를 배치하고, 먼저 128MiB까지 검사한 뒤 재실행했다. 구버전 0.6.0은 처음부터 전체 검색, 신버전은 체크포인트 재개다. 각 3회이며 실행 순서를 번갈아 비교했다. OS 캐시는 비우지 않았다. 표식·경계·바이트 재현성용 자료로, 외부 PDF 앱의 정상 열림을 검증한 시험은 아니다.

| 측정 | 0.6.0 | 0.6.1 |
| --- | ---: | ---: |
| 재실행에서 검색용으로 읽은 바이트 | 268,435,456 | 134,217,735 |
| 최초+재실행 검색 바이트 합계 | 402,653,184 | 268,435,463 |
| 최초+재실행 시간 중앙값 | 566ms | 397ms |
| 최종 원본 바이트 일치 | 매회 5/5 | 매회 5/5 |

검사용 읽기 합계가 약 33% 줄었다. 구조 검사·추출을 위한 추가 읽기와 기존 추출본 검증은 별도이며 시간에는 포함된다. 이는 캐시가 있는 작은 고정 이미지의 엔진 계측으로, 실제 HDD·SSD 속도나 삭제 파일 복구율 추정치가 아니다.

## 검증과 한계

엔진 재개 시험은 검색량 중단, 출력량 중단, 추출 중 취소, 경계 서명, 이미지·설정 변경, 실제 볼륨 재개 거절, 추출본 누락·변조·허용 폴더, 후보 한도, 읽기 오류, 1,100개 불연속 범위, 3회 이어서 검사를 포함한다. 전체 엔진·작업자·배포 UI 검증의 최종 상태는 아래 인수 기록을 따른다.

- 전후 측정 원자료 (개발 당시 로컬 증거; 공개 요약은 docs/EVIDENCE.md)
- 검증 및 배포 인수 기록 (개발 당시 로컬 증거; 공개 요약은 docs/EVIDENCE.md)

이번에 실제 SSD 삭제 시험을 다시 수행하지 않았다. 앞선 0.6.0의 원본 일치 12/50 결과를 새로운 복구율로 재사용하지 않는다. 실제 매체 전체 선택 범위·슬랙·다양한 고장 환경 인수가 남아 F31 전체 완료로 체크하지 않는다.

초기 본문 확보 지연 조사에서는 기존 반복 시험 도구가 삭제 후 출력 위치를 등록하며 약 2.1초를 쓰는 문제가 발견됐다. 다음 실매체 비교에서는 삭제 전에 등록해야 한다. 비슷한 지연에도 회차별 복구 결과가 달랐으므로 이것을 기존 실패의 확정 원인이나 복구율 개선 근거로 삼지 않는다.
