# 0.5.2 검색 대기와 저널 읽기 보강

0.5.1의 실제 삭제 반복 시험은 이전보다 적게 찾고 느렸으며, 정상 원본 복구 성공은 두 버전 모두 0/50이었다. 이 버전의 목표는 확인된 대기 회귀를 제거하고 저널 시작 위치 오류에 대한 제한된 재시도를 추가하는 것이다. 이 변경만으로 실기기 복구율 향상을 주장하지 않는다.

- 일반 사용자 권한으로 실패하던 BitLocker 제공자 두 번의 조회를 생략한다. 암호화 상태는 기존 실패 시와 동일하게 `unknown`이며, 관리자 토큰의 잠금 상태 확인과 원시 장치 읽기의 안전 검증은 유지한다.
- Windows의 저널 읽기 오류 87을 별도 코드로 전달한다. 자동 계산한 최근 시작 위치가 거부되면, Windows가 반환한 보존 시작점에서 동일한 저널 ID와 종료 위치로 한 번 다시 읽는다. 기존 바이트·시간 제한을 유지하고, 사용자가 지정한 위치나 장치 변경 오류에는 이 재시도를 적용하지 않는다.
- 체크리스트 화면의 생성 자료를 기존 인수 문서와 동기화한다. 항목 인수율은 파일 복구 성공률이 아니다.
- 비상주 빈 스트림의 `LastVCN=-1` 표기를 제한적으로 지원한다. 시작 VCN, 파일·할당·초기화 크기가 모두 0이고 플래그와 저장 위치 목록도 비어 있을 때만 허용하며, 크기가 있는 파일을 빈 파일로 바꾸지 않는다.

검증 자료: `E:\RecoveryChat-Regain-20260920`. 실제 C: 볼륨 읽기는 Windows 권한 응답이 없어 아직 재검증하지 못했다. 삭제할 시험용 파일도 아직 만들거나 삭제하지 않았다. 고정 이미지·가상 저널 시험은 실제 SSD 복구율과 구분한다.

참고: [Microsoft READ_USN_JOURNAL_DATA_V0](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-read_usn_journal_data_v0)는 특정 기록에서 읽을 때 해당 기록의 USN을 사용하도록 명시한다. 임의 바이트 차감으로 계산한 위치는 유효한 기록 시작점이라는 보장이 없다. 현재 실기기 오류가 이 원인인지는 실제 읽기 비교로 추가 확인해야 한다.
