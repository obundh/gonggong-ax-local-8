# 0.5.0 — 원본 보관 기반과 간단한 파일 찾기 화면

2026-09-20. 2단계 F07~F12의 구현 및 고정 이미지 검증 기록이다. 실제 장치의 모든 인수 조건을 통과했다는 보고서는 아니다. 필수 항목 인수 점수는 기존 6/54를 유지한다.

## 사용할 수 있는 기능

- Windows 장치의 물리 디스크 식별 정보, 파티션 시작점, 논리·물리 섹터 크기, 파일시스템, 인터페이스, 관측한 잠금 상태를 기록한다. 모르는 값은 `unknown`이다.
- 실제 볼륨 수집 전에 앱·읽기 도우미·작업 공간·로그·캐시·임시 폴더·출력의 물리 디스크 관계를 확인한다. 같은 디스크이거나 관계가 확인되지 않으면 시작하지 않는다. 실제로 열린 읽기 계층의 식별 정보와 논리 섹터 크기도 대조한다.
- 같은 볼륨 ID·용량·디스크 번호를 가진 교체 장치라도 물리 식별자·파티션·섹터 계층이 다르면 기존 선택으로 수집하지 않는다. 목록 갱신이 이전 선택을 몰래 바꾸지 않게 하고 연결을 연 직후에도 대조한다.
- Windows 권한 대기와 읽기 연결 이후, 출력 폴더나 수집 이력을 만들기 전에 저장 위치·작업 공간·실행 위치의 물리 분리를 다시 검사한다. 대기 중 장치가 바뀌거나 원본 디스크를 가리키면 수집을 시작하지 않는다.
- 선택한 볼륨 또는 raw 이미지의 전체 노출 범위를 별도 `image.raw`로 보관한다. 선택한 볼륨 밖의 물리 디스크 영역을 수집했다는 뜻은 아니다.
- `acquisition.json`과 `acquisition.journal`에 크기, SHA-256, 범위, 읽기 실패 구간, 중단 사유, 체크포인트와 재개 이력을 남긴다. 읽기 실패로 채운 0과 원래 읽힌 0을 구별한다.
- 중단한 고정 이미지 수집은 원본과 기존 출력의 동일성을 다시 확인한 뒤 재개할 수 있다. 실행 중인 실제 볼륨은 서로 다른 시점의 자료를 하나로 이어 붙이지 않고 새 수집으로 시작한다.
- 완성된 보관본은 전체 해시와 이력을 다시 확인한 뒤 기존 삭제 기록 검색 엔진에 연결한다. 불완전하거나 바뀐 보관본은 완성된 이미지로 열지 않는다.

## 화면

첫 화면에는 찾을 위치, 삭제된 기간, 선택적인 이름 입력, 찾기 버튼을 둔다. 검색 방법·보호 점검·진행 단계·통계·개발 체크리스트는 필요할 때 펼친다. 경고, 불완전 검색, 진행 표시, 중단 버튼은 접힌 세부 정보에 숨기지 않는다. 목록과 미리보기는 검색 후 표시한다.

원본 보관은 `도구 · 안내 → 원본 보관 · 이미지`에서 시작한다. 선택한 범위 전체 크기만큼 공간이 필요하며 확인 화면에서 시작 버튼을 눌러야 한다. 일반 파일 찾기의 필수 선행 단계는 아니다.

## 검증 자료

검증 로그·고정 이미지·화면 캡처는 `E:\RecoveryChat-Stage2-20260920`에 분리해서 보관한다.

- core/service 시험: 정답 이미지와 출력 해시, 읽기 오류와 0 구별, 제한된 재시도, 취소, 재시작 후 재개, 변경된 원본·출력 거절, 하드링크를 통한 원본 변경 방지, 검사 중 파일 변경, 공간 부족 주입, 실제 NTFS 검색 엔진 연결.
- `scripts/verify-stage2.mjs`: 동일한 생성 NTFS 이미지를 두 번 실제 수집하고 각각 재분석했다. 두 번 모두 후보 10개와 같은 후보 근거가 나왔고 원본 SHA-256은 유지됐다. 이 시험의 정답은 생성 이미지에만 적용된다.
- 실제 Windows 관측은 장치 메타데이터만 읽었다. 실행 중인 C:를 수집하거나 사용자 파일을 새로 삭제하지 않았다. 메타데이터가 같아도 C:의 내용이 그대로였다고 주장하지 않는다.
- Electron 화면 시험은 생성 이미지의 실제 수집·검증·재검색과 기존 채팅·검색·미리보기·저장 흐름을 확인한다. 파일 선택 대화상자와 일부 장치 메타데이터만 시험 입력으로 대체한다.

## 남아 있는 검증과 제한

실제 USB 분리, 실제 목적지 공간 고갈, 512e/4Kn 장치별 전체 수집, 잠긴 BitLocker 볼륨 거절의 실장치 인수는 남아 있다. 현재 해당 오류 경로는 생성 입력·주입 시험 근거와 구분한다. E01/VHDX 직접 수집·변환, 물리 디스크 전체 수집, RAID/다중 디스크 볼륨 수집은 지원하지 않는다.

고정 이미지의 일치 검증은 SSD에서 지운 내용이 남아 있음을 보장하지 않는다. 읽기 전용 요청은 Windows·다른 프로그램·컨트롤러의 변화를 정지시키지 않는다. 전원·TRIM·암호화 상태에 따른 절차는 `stage2-preservation-protocol.md`를 따른다. 이번 작업은 기존 실환경 `JOURNAL_READ_FAILED` 원인을 해결한 변경이 아니다.

보관본 재개 전에는 전체 원본 크기만큼의 여유 공간을 보수적으로 다시 요구한다. 디스크가 새로운 메타데이터조차 쓰지 못하면 마지막 체크포인트 이후의 중단 사유를 기록하지 못할 수 있다. 중단 자료는 완성으로 표시하지 않는다.
