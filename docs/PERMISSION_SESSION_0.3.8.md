# 0.3.8 Windows 권한 재사용

검색마다 새 워커가 별도 관리자 도우미를 실행하던 구조를 바꿨다. 메인 프로세스의 WindowsVolumeSession이 읽기 전용 도우미 연결을 소유하고, 워커는 선택한 장치에 고정된 읽기 요청만 전달한다. 드라이브 전환은 같은 도우미에서 기존 핸들을 해제하고 새 볼륨을 열며 식별 정보를 대조한다. 검색 종료는 해당 사용 연결만 해제하고, 앱 종료는 도우미 연결을 닫는다.

앱 화면은 asInvoker로 실행한다. UAC 설정·서비스·예약 작업을 추가하거나 변경하지 않는다. 첫 권한 연결, 앱 재실행 또는 끊긴 도우미를 새로 연결하는 경우에는 Windows 허용이 필요하다.

## 2026-09-14 검증

- 엔진 시험 260개: 통과 259, 건너뜀 1, 실패 0. `output/permission-session-engine-tests.tap`.
- 0.3.8 배포 EXE 화면 시험 4/4 통과. `output/permission-session-packaged-desktop-tests.tap`.
- 실제 워커를 사용한 연속 검색·이전 결과 미리보기·정답 해시 일치 복구·작업 퇴출·앱 종료 경합 시험 통과. 볼륨 본문은 합성 메모리 공급자를 사용했으며 실제 UAC 시험과 구별한다.
- 세션 시험은 다른 볼륨과 동시 요청에서 관리자 실행 1회, 권한 거절 시 중복 실행 방지, 장치 교체 시 기존 연결 거부, 첫 응답 대기 중 종료를 확인한다.
- 컴파일한 native helper의 실제 보안 named pipe에서 `release → hello → close` 통과. 원시 볼륨을 열지 않는 프로토콜 시험이다.
- 실제 0.3.8 메인 프로세스의 세션으로 C: → E: → C: 각 512바이트 읽기를 시도했다. Windows 권한 요청은 1회 발생했으나 보호된 허용 창에 도구가 접근하지 못해 연결 시간 초과로 종료됐다. 실제 읽기 0회이며 실제 C/E 권한 재사용 성공으로 보고하지 않는다. `E:/RecoveryChat-0.3.8/permission-session-live-check.json`.
- 엔진 4개 파일과 native EXE의 소스·배포본 SHA-256 일치를 확인했다. `E:/RecoveryChat-0.3.8/RecoveryChat-0.3.8-win-x64.zip`을 생성했고 새 버전을 실행해 두었다.

이 변경은 반복 권한 요청 개선이다. 앞선 PDF 삭제 시험의 복구 실패, 정밀 검색 후보 한도, 파일 형식 필터 문제를 해결한 것으로 집계하지 않는다.
