# Stage 2 F10/F11 보존·증거 프로토콜

이 문서는 Stage 2 시험에서 무엇을 관측하고 무엇을 증명하지 않는지 정한다. 앱은 이 절차에서 실제 장치를 열거나, 파일을 삭제하거나, 관리자 권한을 요청하거나, 전원·암호화·저장장치 설정을 바꾸지 않는다.

## 시험군과 주장 범위

F10은 서로 다른 두 시험군을 분리한다.

| 시험군 | 수행할 관측 | 허용되는 주장 | 허용되지 않는 주장 |
| --- | --- | --- | --- |
| 고정 raw 이미지 | 시험 전후 같은 이미지 파일의 전체 해시와 수집 이력을 확인 | 기록된 방식으로 계산한 해당 이미지 바이트가 전후 일치하거나 불일치함 | 이미지 생성 뒤 원래 디스크가 변하지 않았음 |
| 실행 중인 C: 시스템 볼륨 | 시작 전후의 읽기 전용 장치 목록, 장치 식별자, 여유 공간 등 메타데이터를 기록 | 기록 시점의 메타데이터 차이 또는 미관측 | C: 전체가 정적 스냅샷이었음, 데이터가 변하지 않았음 |
| 그 밖의 실행 중 볼륨 | 위 라이브 관측과 같은 한정된 메타데이터 기록 | 기록된 관측값 | 라이브 볼륨 전체의 무변경 또는 완전성 |

따라서 이번 기본 실행은 **고정 이미지 fixture의 해시 검증**과 **읽기 전용 C: 인벤토리의 전후 기록**이다. 라이브 C:의 전체 원시 이미지 수집은 이 실행에 포함하지 않는다. `describeTrialContext`와 `compareDeviceObservations`의 결과는 이 분류를 직렬화 가능한 형태로 남기며, 메타데이터 비교는 항상 `dataUnchanged: "not-proven"`을 유지한다.

## F11: 읽기와 보존의 실제 경계

읽기 전용 핸들은 이 도구가 쓰기 접근을 요청하지 않았다는 뜻이다. Windows의 `CreateFile`은 요청 접근과 공유 모드를 별도로 받으며, 장치에도 적용될 수 있다. 그러므로 이 핸들 하나가 운영체제, 파일 시스템, 다른 프로그램 또는 장치 펌웨어의 쓰기를 멈춘다는 보장은 없다. [Microsoft CreateFile 문서](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea)

SSD에서는 삭제가 파일 시스템 메타데이터 변경으로 끝날 수 있고, Windows/NTFS는 일부 삭제 같은 일반 작업에서 TRIM 힌트를 보낼 수 있다. Microsoft는 TRIM/Unmap을 하위 저장장치에 대한 힌트로 설명하며 장치 응답을 기다리지 않는다고 명시한다. 이 도구는 TRIM을 요청하거나 재요청하지 않지만, 호스트의 기존 작업, 컨트롤러의 가비지 컬렉션, 웨어 레벨링과 그 밖의 내부 상태는 이 관측으로 확인하거나 통제할 수 없다. [Microsoft TRIM/Unmap 설명](https://learn.microsoft.com/en-us/windows/compatibility/new-api-allows-apps-to-send-trim-and-unmap-hints)

BitLocker 잠금 여부도 수집 가능성과 증거 범위를 바꾼다. Microsoft의 `GetLockStatus` 문서는 상태가 Windows에서 볼륨 내용을 접근할 수 있는지를 나타내며, 현재 실행 중인 Windows 볼륨은 항상 접근 가능하고 잠글 수 없다고 설명한다. 관측 결과가 잠김·해제 상태를 보인다고 해서 키를 보유하거나, 복호화 바이트를 보존했거나, 다른 상태 전이가 없었다는 증거는 아니다. [Microsoft GetLockStatus 문서](https://learn.microsoft.com/en-us/windows/win32/secprov/getlockstatus-win32-encryptablevolume)

## 안전한 기록 절차

관측 전후에 시간, 도구 버전, 원본 식별자, 파일 시스템이 제공한 장치 메타데이터, 고정 이미지의 해시 알고리즘과 해시값을 분리된 증거 기록에 남긴다. 값이 없으면 `unknown` 또는 `null`로 남기고 추정값을 채우지 않는다. 고정 이미지의 해시가 다르면 결과를 불일치로 기록하고 이후 해석을 멈춘다. 라이브 볼륨은 식별자나 여유 공간이 같아도 메타데이터 관측 일치로만 기록한다.

이 절차는 전원 차단, 재부팅, 잠금, 잠금 해제, TRIM 재요청, 쓰기 차단 장치 제어를 자동으로 실행하지 않으며 그러한 명령을 사용자에게 제공하지 않는다. SSD에 대해 사용자가 아무 조건 없이 전원을 끄라고 안내하지 않는다. 장치 모델, 현재 전원 상태, 암호화 상태 중 하나라도 확인되지 않은 상태에서 전원을 바꾸는 시험은 중단하고, 관측 기록만 보존한다. 복구 키나 비밀번호는 사용자가 별도로 통제·보관하고 이 도구의 로그, 진단 번들, 시험 기록에 적거나 전송하지 않는다.

## 알려진 증명 한계

이 절차는 고정 이미지의 같은 바이트열 비교와 라이브 시스템의 제한된 관측을 구분한다. 라이브 환경에서는 다른 호스트 쓰기, 캐시, 파일 시스템 메타데이터, 저장장치 펌웨어 상태와 관측되지 않은 내부 동작이 있을 수 있다. 그러므로 F10/F11 기록은 데이터 복구 가능성, 삭제 데이터의 잔존, 전원 동작의 안전성, 또는 라이브 원본 전체 무변경을 증명하지 않는다. 이 문서는 Stage 2 전체 승인이나 완료를 주장하지 않는다.
