# 0.5.8 — 4단계 보강: 폴더 인덱스의 옛 이름 흔적

파일 관리 기록이 다른 파일에 재사용돼도 부모 폴더 인덱스의 남는 영역에 이름 형태의 기록이 남을 수 있다. 0.5.8은 이를 **폴더 기록 흔적**으로 별도 표시한다. 이 흔적만으로 삭제 여부·원래 전체 경로·본문 위치를 확정하지 않는다.

## 범위와 제한

- 실제 Windows NTFS의 빠른 검색·빈 기록 추가 탐색에서 이미 발견한 삭제 기록과 표시할 삭제 이력의 부모 참조만 사용한다. 드라이브 전체 폴더 열거를 추가하지 않는다. 이미지 제품 검색 경로에는 이번 추가 분석을 연결하지 않았다.
- 최대 32개 부모 폴더를 확인한다. 현재 사용 중인 같은 세대의 단순 디렉터리만 지원하며 확장 속성 목록·재분석점·압축·희소·미초기화 인덱스는 제외한다.
- resident `$I30` INDEX_ROOT와 INDEX_ALLOCATION의 **앞 8개 블록 범위 중 인덱스 비트맵에서 사용 중인 블록**을 확인한다. 읽기 단위는 최대 64KiB, 루트 값·비트맵·인덱스 읽기와 재확인을 합쳐 최대 4MiB로 제한한다. 이 수치는 MFT·할당 비트맵 등 보조 구조의 전체 디스크 I/O를 합친 수치가 아니다. 1.5초의 작업 시간 예산을 읽기·후보 처리 경계에서 확인하며, 진행 중인 단일 OS 읽기를 강제로 중단하는 시간 보장은 아니다. 일시정지 시간은 이 예산에서 제외한다.
- 각 노드의 정상 항목이 끝난 뒤부터 선언된 할당 끝까지 8바이트 정렬 위치만 해석한다. 사용 중인 항목 사이의 빈틈, MFT 속성 바깥의 여유 영역, 해제된 인덱스 버퍼, 전체 디렉터리 트리 탐색, `$LogFile` 해석은 이번 범위에 없다.
- 헤더·경계·활성 항목·INDX 섹터 fixup·VCN·부모 참조·파일 이름·UTF-16·크기·시각을 검사한다. 같은 활성 항목 또는 현재 MFT의 같은 세대·이름·부모와 일치하는 파일은 단서에서 제외한다. 구조에 맞는 잔여 바이트라도 역사적 진위와 삭제 사실까지 증명되지는 않는다.
- 각 단위에서 최대 64개, 검색당 최대 128개 단서를 보관한다. 기존 본문 후보·삭제 이력의 보관 한도를 먼저 확보한다. 범위 초과·확인 실패는 경고와 통계로 남긴다.
- 폴더 기록·할당 상태·읽은 인덱스 및 비트맵을 다시 확인한 뒤 후보를 표시한다. 원시 정보 바이트·SHA-256·위치·폴더 참조·세대를 후보 근거로 보존하고, 저장된 후보를 표시할 때 재해석한다. 이는 내부 일관성 검사이며 근거 전체를 함께 위조하는 공격에 대한 인증은 아니다.

## 사용자에게 표시하는 정보

옛 이름 형태의 흔적, 발견한 현재 폴더의 이름과 기록 번호, 기록된 크기·수정 시각을 표시한다. 기록된 수정 시각은 삭제 시각과 분리한다. 본문 크기·삭제 시각·삭제 여부는 미확정이고, 저장·미리보기·즉시 본문 확보를 허용하지 않는다. 같은 드라이브 정밀 검색으로 이어가도 이 단서의 본문이라고 자동 연결하지 않는다.

## 검증과 완료 상태

`E:/RecoveryChat-Stage4d-20260926/`에 이전 0.5.7 소스 스냅샷·해시, 시험 로그, 패키지 확인 자료를 보관한다. 동일 NTFS 이미지에서 MFT가 재사용된 옛 파일의 이름 흔적은 **0.5.7 0/1 → 0.5.8 1/1**이었다. 대조 TXT의 원본 SHA-256 일치는 양쪽 **1/1**, 기존 후보 전체 정보와 원본 이미지 해시는 유지됐다. resident 루트와 할당된 INDX 블록을 각각 시험했으며 현재 파일 중복·부모 세대 불일치·비트맵 해제·USA 손상·읽기 중 변경·보관 한도·취소도 확인한다.

소스 검증은 엔진 459개 통과·실패 0개·권한 제한 시험 1개 건너뜀, 데스크톱 화면 9/9 통과다. 배포 패키지 검증 결과는 같은 증거 폴더의 별도 로그와 해시 확인 자료에 기록한다.

실제 사용자 파일을 새로 삭제하거나 SSD 복구율을 재측정하지 않았다. 새로 찾은 이름 흔적을 본문 복구 성공으로 집계하지 않는다. **F22/F23 일부 구현, 필수 기준 17/54(31.5%) 유지**이며 4단계 전체 인수는 아직이다.

형식은 [libyal NTFS 사양](https://github.com/libyal/libfsntfs/blob/main/documentation/New%20Technologies%20File%20System%20%28NTFS%29.asciidoc)의 구조 설명을 참고해 자체 구현했다. 외부 라이브러리나 사양 본문을 패키지에 포함하지 않았다.
