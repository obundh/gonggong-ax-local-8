# 0.5.3 — 발견 시점 본문 확보

Windows NTFS의 삭제 이력·빈 기록 검색에서 문서와 이미지를 발견하면, 검색 종료 전에 본문 확보를 시도한다. 앱 작업 공간이 원본과 다른 물리 디스크인지 먼저 확인한다. 최종 저장 폴더는 기존처럼 후보를 선택한 뒤 지정한다.

- 후보마다 현재 기록·할당 상태를 재검사하고, 본문 읽기와 저장 후에도 다시 검사한다. 그 사이 기록이 바뀌면 확보 성공으로 취급하지 않는다.
- 검증된 확보본이 있으면 미리보기와 저장은 확보본에서 수행한다. 확보본 크기·파일 식별 정보·SHA-256을 다시 확인하며, 변조되면 거부한다.
- 파일당 16 MiB 이하의 지원 문서·이미지, 작업당 최대 256 MiB·64회 시도·확보 처리 20초 예산이다. 여유 공간 64 MiB를 남기며, 한도 뒤에도 후보 검색은 계속한다. 보조 스트림은 기존에 지원하는 resident Zone.Identifier만 보존한다.
- 확보 실패와 한도 초과는 후보의 preservation 정보에 남긴다. 원본 기록을 다시 확인하는 기존 저장 경로도 유지한다.
- 확보본은 작업 공간의 candidate-jobs/<작업 ID>/captured에 남는다. 현재 실행 세션에서 저장할 수 있으며 앱 재시작 후 확보본 재연결은 지원하지 않는다. 자동 정리하지 않는다.
- 같은 파일·이름·부모의 이름 변경 기록 직후 CLOSE가 누적 사유만 반복한 경우 원래 이름 복원을 막지 않도록 수정했다. 다른 이름 변경이나 불명확한 기록은 계속 거부한다.

`본문 확보`는 정상 문서나 삭제 전 원본과의 일치 보장이 아니다. 손상·형식 검사·실제 원본 대조를 구분한다. 라이브 볼륨 검사만으로 TRIM·물리적 소거 원인을 확정하지 않는다.

합성 통합 시험은 후보 표시 뒤 원본 기록을 재사용해 기존 저장 경로가 실패하는 상황에서도, 앞서 확보한 본문으로 정확히 저장되는지 확인한다. 실제 SSD 성과는 별도 실기기 시험 보고서로 판정한다.
