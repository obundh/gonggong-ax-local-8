# 0.5.7 — 4단계 보강: 삭제된 휴지통 정보 단서

삭제된 `$I` 정보 파일의 본문이 남아 있는 경우 원래 이름·원래 경로·기록된 크기·휴지통 이동 시각을 읽어 **휴지통 정보 단서**로 표시한다. 본문이 든 `$R` 파일과 이름 뒷부분·크기가 같아도 같은 파일이라고 연결하지 않는다. 단서 발견은 문서 본문 복구가 아니다.

## 구현 범위

- 실제 Windows NTFS의 빠른 검색·빈 기록 추가 탐색에서 이미 발견한 `$I` 기록만 확인한다. 전체 MFT나 다른 드라이브를 추가로 열거하지 않는다. 이미지의 기존 검색 경로에는 아직 연결하지 않았다.
- 읽기 전후에 삭제 기록의 세대·지문·할당 상태와 현재 SID 폴더 → `$Recycle.Bin` → 루트의 참조·세대·지문을 확인한다. 부모 재사용, 모호한 이름·하드링크, 재분석 지점, 복잡한 부모 속성은 보수적으로 거절한다. 현재 부모 연결 검사는 과거 디렉터리 슬랙 분석이나 역사적 경로의 완전한 증명이 아니다.
- 기존 본문 읽기의 할당·확장 기록·변경 검사를 재사용한다. 한 검색에서 정보 파일 확인은 최대 128번, 한 정보 파일은 최대 65,564바이트, 누적 정보 본문은 최대 8MiB로 제한한다. 이 수치는 보조 파일시스템 구조 읽기까지 포함한 총 디스크 I/O 한도가 아니다. 한도에 도달하면 경고를 남긴다.
- v1/v2 길이·UTF-16·종료 문자·경로·크기·FILETIME을 확인한다. 정보 본문의 SHA-256, 기록과 부모 연결, 원시 정보 바이트를 후보 근거로 보존한다. 저장된 근거의 불일치는 이름·경로 표시에서 제외한다. 내부 일관성 검사이며 조작자가 근거 전체를 함께 위조할 때 이를 인증하는 전자서명은 아니다.
- `$I`의 시각은 **휴지통 이동 시각**으로 표시한다. 영구 삭제 시각과 본문 크기는 미확인으로 남긴다. 삭제 기간의 확정 일치로 세지 않으며, 시각 미확인 항목을 제외하면 목록에서 제외된다.
- 단서는 저장·미리보기·즉시 본문 확보에서 제외한다. 같은 드라이브의 정밀 검색 버튼은 제공하되 새 후보와의 동일성은 확정하지 않는다. 원래 경로의 과거 드라이브 문자를 따라 다른 드라이브를 자동 선택하지 않는다.

## 검증과 제한

검증 자료는 `E:/RecoveryChat-Stage4c-20260926/`에 보관한다. 파서의 정상·손상·경로·증거 불일치 시험, NTFS 고정 이미지 연결 시험, 저장된 후보 검색·저장 방어 시험, Electron 화면 시험을 구분한다. 합성 이미지 성과를 실제 SSD 삭제 복구율로 집계하지 않는다.

같은 고정 NTFS 이미지를 0.5.6과 0.5.7에 입력했다. 삭제 `$I` 1개에서 원래 이름·경로를 해석한 결과는 **0/1 → 1/1**, 대조 TXT 1개의 원본 SHA-256 일치는 **1/1 → 1/1**이었다. 같은 접미사의 `$R`은 별도 후보로 남았고 원본 이미지 해시는 불변이었다. 엔진 전체 시험 **442개 통과·1개 건너뜀·실패 0**, 소스 Electron 화면 시험 **8/8 통과**. 건너뛴 시험은 Windows 심볼릭 링크 생성 권한(EPERM)으로 실행하지 못한 기존 시험이다.

이번에는 사용자 파일을 새로 삭제하거나 실기기 복구율을 재측정하지 않았다. 기존에 남아 있던 `$I` 본문까지 덮어써지거나 읽을 수 없으면 추가 단서를 얻지 못한다. 본문 복구율 개선은 아직 입증하지 않았다.

F22/F23 일부 구현이다. **필수 기준 17/54(31.5%)**, 4단계 전체 인수는 미완료다. 삭제 정보와 본문을 입증하여 연결하는 기능, 디렉터리 인덱스 슬랙, `$LogFile` 잔존 기록 분석은 남아 있다.

형식 사실은 [libyal Windows Recycle.Bin file formats](https://github.com/libyal/dtformats/blob/main/documentation/Windows%20Recycle.Bin%20file%20formats.asciidoc)를 참고해 자체 구현했다. 외부 복구 라이브러리나 해당 문서 본문을 포함하지 않았다.
