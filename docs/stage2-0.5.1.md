# 2단계 보강 — 0.5.1

원본 보관 중 저장 공간이 부족해져도 마지막으로 검증 가능한 수집 기록을 유지하도록 보강했다. 파일시스템 용량과 실제 볼륨 읽기 길이를 분리하고, 원본의 논리·물리 섹터 크기와 선언된 형식이 모순되면 수집을 거절한다. 장치 관측 보고서에는 바뀐 항목을 구분해 남긴다.

실제 시험용 NTFS 볼륨은 파일시스템 용량이 251,588,608바이트였지만 파티션과 원시 읽기 계층의 길이는 251,592,704바이트였다. 이전에는 이 4,096바이트 차이를 장치 변경으로 오인했다. 정확히 확인한 파티션 길이와 열린 핸들의 길이를 대조하도록 수정했다. 파일시스템 뒤쪽 구간도 읽기 전용 핸들에서 읽되, 파티션 경계와 섹터 정렬 검사는 유지한다. [Microsoft의 확장 DASD 읽기 설명](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_allow_extended_dasd_io)

- 지원 수집 범위: Windows가 노출하는 단일 볼륨의 전체 범위와 raw/dd 고정 이미지. 전체 물리 디스크·E01·VHDX 직접 해석은 지원하지 않는다.
- 실행 중 볼륨의 수집은 스냅샷이 아니다. 앱의 읽기 전용 핸들은 운영체제의 쓰기나 SSD 내부 정리 작업을 멈추지 않는다.
- 재개는 원본과 이미지를 다시 검증할 수 있는 고정 이미지에 한정한다. 실행 중 볼륨은 새 수집으로 시작한다.
- 장치 교체, 잠긴 볼륨, 512e/4Kn 조건을 주입한 시험은 실제 해당 장비의 검증과 구분한다.
- 장치의 길이·구성·식별 정보를 다시 읽을 수 없으면 즉시 중단한다. 연결 해제 오류를 반복 읽기나 0 채우기로 처리하지 않는다.
- 파일 기반 가상 장치는 실제 보관 장치를 확인할 수 없으므로 일반 볼륨 수집에서 거절한다. 시험용 VHD의 원시 읽기 검증은 이 허용 판정을 우회한 엔진 시험으로 따로 기록한다.

이번 버전은 수집·보존 계층 보강이다. 기존 USN의 `JOURNAL_READ_FAILED`, 자동 원래 이름 연결, 새로운 본문 복구 알고리즘을 수정한 버전으로 해석하면 안 된다.

검증 자료와 같은 다섯 파일을 새로 삭제하는 10회 비교 시험의 결과는 별도 장부에 기록한다. 후보 발견, 파일 저장, 원본 SHA-256·크기 일치, 이름 복원은 각각 집계한다. 이 비교 시험의 후보 채점은 검색 종료·후보 고정 후 휴지통 이름 대응표를 사용하므로, 자동 원래 이름 인식 성적으로 간주하지 않는다.

## 최종 검증 결과 — 2026-09-20

- 자동 검사 357개 중 356개 통과, 1개는 Windows 심볼릭 링크 생성 권한 부족(EPERM)으로 건너뛰었다. 배포본 Electron의 고정 이미지 보관·검증·재검색 흐름 1회와 독립 변경 경로 검사 73개가 통과했다.
- 시험용 NTFS 볼륨 251,592,704바이트를 모두 수집했고, 두 번째 원본 읽기의 SHA-256과 일치했다. 실제로 소유 VHD를 분리한 최종 시험은 16MiB의 유효한 부분 이미지에서 즉시 멈췄으며 0 채움은 없었다.
- 제한된 시험용 VHD 출력 공간을 실제로 소진시켜 ENOSPC를 확인했다. 유효한 230,686,720바이트 체크포인트를 보존했고, E:로 옮긴 부분 자료를 같은 고정 이미지에서 이어 읽어 전체 해시가 일치했다.
- 제품의 가상 장치 거절 게이트를 우회한 원시 엔진 시험과 실제 제품의 허용 판정을 구분한다. C:→E:의 실제 메타데이터 분리도 확인했으나, C: 전체 이미지가 들어갈 별도 저장 공간이 없어 전체 C: 수집은 실행하지 않았다.
- 체크리스트 F08~F12는 명시한 범위에서 인수했다. 실제 USB 브리지·4Kn·잠긴 BitLocker 장비 인수가 없어 F07은 보류다. 필수 계획 이행은 11/54(20.4%)이며 복구율이나 포렌식 능력 점수가 아니다.

같은 다섯 파일의 새 복사본을 매회 휴지통에 넣고 해당 항목만 삭제했다. 총 12회 중 첫 2회는 자동화의 출력 하위 폴더 누락으로 검색 전에 중단됐고 기록을 보존했다. 보충 2회를 포함한 유효 10회·50건으로 집계했다. 프로그램 화면을 10회 조작한 시험이 아니라, 배포본 엔진·Windows 읽기 도우미의 실행 시험이다.

이번에 저장한 1개는 PNG로 정상 해석되지 않았다. 복구 성능 개선은 확인되지 않았다. 같은 시점의 동일 이미지 A/B 시험이 아니라 실행 중 C:에서 시간과 상태가 달라진 반복 시험이므로, 차이를 버전 변경의 인과 효과로 단정하지 않는다. 검색 범위가 불완전한 상태와 저널 읽기·기록 해석 오류도 그대로 기록했다. 본문 소멸이나 TRIM이 원인이라고 확정하지 않았다.

후보 발견은 검색과 후보 내보내기가 끝난 후 시험용 휴지통 이름 대응표로 대조한 값이다. 사전 파일명·파일 ID를 검색에 주입하지 않았고, 시험용 대응표를 자동 이름 복원 기능으로 계산하지 않았다.
