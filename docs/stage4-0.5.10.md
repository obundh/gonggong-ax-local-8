# 0.5.10 — 폴더 탐색 단계의 단서 한도 분리

0.5.9의 실제 C: 시험에서 20번의 검색 중 17번은 앞선 폴더 슬랙 단서가 공유 한도 128개를 채웠다. 그 결과 사용 해제된 인덱스 단계는 디렉터리·블록을 하나도 검사하지 않았다. 0.5.10은 각 단계에 별도 128개 한도를 적용해 이 원인으로 추가 탐색이 생략되는 문제를 고친다.

## 보존하는 조건

- 기존 본문 후보, 삭제 이력, 앞선 폴더 슬랙 결과를 먼저 보존한다. 이를 제거하거나 반으로 줄여 새 단서 자리를 만들지 않는다.
- 폴더 슬랙 최대 128개와 사용 해제 블록 최대 128개로, 폴더 단서 합계는 최대 256개다. 전체 `maxCandidates` 한도는 그대로 적용한다. 전체 한도를 이미 채웠다면 추가 단계가 생략될 수 있다.
- 각 단계의 최대 32개 관측 부모, 읽기·재확인 4MiB, 처리 경계에서 확인하는 1.5초 작업 시간 예산은 그대로다. 두 단계 합계 최대 8MiB/3초이며 보조 MFT·할당 비트맵 I/O는 이 바이트 합계 밖이다. 단일 OS 읽기를 강제 중단하는 벽시계 시간 보장이 아니다.
- 사용 해제 블록은 첫 64개 인덱스 위치 중 폴더당 최대 8개를 확인한다. 폴더 비트맵 0·볼륨 클러스터 비트맵 1, 구조·세대·해시 재확인 조건을 유지한다.
- 추가 단서는 여전히 `metadata-only`다. 삭제 사실, 원래 전체 경로, 본문 위치를 확정하지 않으며 미리보기·본문 준비·저장을 허용하지 않는다.

## 실행 여부

두 단계 통계에 실제 단서 한도 `clueLimit`, 실행 상태 `execution`, 생략 이유 `skippedReason`을 기록한다. 전체 후보 한도 소진, 관측한 부모 없음, 지원하지 않는 엔진을 구별한다. `skipped`는 검색해 봤지만 단서가 없었다는 뜻이 아니다. 제한·구조 오류 경고와 이전 후보 보존은 기존 동작을 유지한다.

## 검증과 범위

고정 NTFS 이미지에서 앞선 128개 단서를 유지한 채 사용 해제 블록의 추가 단서를 읽는지, 전체 후보 한도를 넘지 않는지, 기존 복구 본문의 SHA-256과 입력 이미지가 그대로인지 확인한다. 기준 소스와 전체 변경·시험·패키지·검토 자료는 `E:/RecoveryChat-Reinforcement-0510-20260926/`에 보존한다.

실제 SSD 시험은 기존 5개 자료의 새 복사본을 10회 사용하며, 알려진 파일명·파일 ID·원본 바이트를 검색 입력에 넣지 않는다. 후보 고정 뒤 별도 채점하며 이름 발견·파일 저장·원본 크기 및 SHA-256 일치를 분리한다. 실제 수치는 `E:/RecoveryChat-RecoveryRate-0510-20260926/`의 측정 결과를 따른다. 변화하는 SSD에서 서로 다른 시점의 수치만으로 버전의 인과 효과를 단정하지 않는다.

이 수정은 메타데이터 탐색 기회를 확보한다. 이미 소실된 본문을 다시 만드는 기능이 아니며, 이 변경만으로 문서 복구율 상승을 보장하지 않는다. `$LogFile`, 노드 내부 빈틈, 단서와 본문 연결 등은 남아 있다. **F22/F23 일부 보강, 필수 기준 17/54(31.5%) 유지**, 4단계 전체 인수는 미완료다.
