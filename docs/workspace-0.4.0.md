# 0.4.0 — 단계별 복구 작업 공간

체크리스트를 읽을 수 있는 별도 화면과, 실제 엔진 이벤트로 갱신되는 복구 단계를 연결했다. 기본 화면은 원본 보호 / 삭제 기록 / 본문 복구 / 정밀 검색 / 다른 사본의 다섯 경로와 검색 조건·파일 목록·미리보기로 구성한다. 채팅 모드와 작업 중 모드 전환 잠금은 유지한다.

진행 상태는 `start`, `progress`, `complete`, `recover-complete`, `error`, `cancelled` 등의 실제 작업 이벤트에서만 결정한다. 부분 검색·경고는 확인 필요, 실행하지 않은 단계는 대기로 표시한다. 파일 저장 수와 삭제 전 원본 일치 확인 수를 분리한다. 과거 작업이나 다른 원본으로 이동하면 이전 화면의 단계 관측을 그대로 붙이지 않는다.

원본 보호 점검은 점검 당시의 원본과 출력 위치에 한정한다. 자동 선택 표시가 그대로여도 실제 검색 원본이 바뀌거나 출력 ID·경로가 바뀌면 점검 표시를 비운다. 점검 전용 출력 위치를 별도로 유지하지 않아 이전 출력이 현재 출력을 가리는 일을 방지한다.

전체 체크리스트는 정식 54개 필수 / 6개 조건부 연구 항목과 기존 인수 6개를 표시한다. F04의 실제 삭제 이력 읽기 오류는 별도 경고다. UI 변경으로 개발 인수 수나 복구 성공률을 올리지 않는다. `ui/checklist-data.mjs`는 원문에서 생성하며 `node scripts/build-checklist-data.mjs`로 갱신한다.

2단계 F07/F08의 첫 구현으로 장치·작업 공간·선택한 출력 위치를 다시 확인하는 메타데이터 점검을 추가했다. 같은 물리 디스크·장치 변경은 차단 조건으로 보고하고, 확인하지 못한 관계·섹터·암호화 정보는 미확인으로 남긴다. 점검은 원시 볼륨 읽기, 권한 상승, 전체 해시, 이미지 수집을 수행하지 않는다. 기존 실제 검색·저장 보호 검사는 그대로 유지한다. 상세 계약은 `stage2-readiness.md`에 있다. 2단계 전체 완료는 아니다.

검증 범위: 기존 Electron 동작 회귀, 신규 단계/손상 상태 IPC 표시, 체크리스트 원문 일치, 장치 점검 단위 시험, 실제 데스크톱/좁은 창/확대/동작 축소 렌더링. 사용자 파일을 새로 삭제하는 시험은 하지 않았다. UI 상태 시험용 데이터와 실제 장치 메타데이터 점검은 별도 증거로 남긴다. 스크린 리더 전체 검증 및 일반 성능 지표의 현장 측정은 수행하지 않았다.
