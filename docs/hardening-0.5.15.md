# 0.5.15 준비 지연·큰 파일 형식 판정 보강

## 수정

- 같은 검색에서 두 번 수행하던 원본 장치 목록 조회를 하나로 묶었다. 새 검색마다 새로 조회하고, 메인 프로세스의 일회용 확인 정보만 전달한다. 다른 작업·장치·세대에서 사용하거나 재사용할 수 없다. 발급 후 5초가 지나면 다시 조회한다. 별도 물리 디스크 검사 완료 전에는 작업 폴더·워커·권한 연결을 시작하지 않는다.
- 실제 핸들의 장치 확인과 각 읽기 확인은 유지한다. 닫힌 도우미는 새 검색에서 첫 시도로 재연결하며 이전 읽기 권한은 다시 쓰지 못한다. 취소·시작 실패·워커 종료 시 미사용 확인 정보를 폐기한다.
- 8MiB를 넘는 파일도 확장자와 헤더를 비교한다. 이름만 PNG/JPG/PDF이고 내용이 0으로 채워진 파일은 `format-mismatch`로 표시한다. 저장 해시 검증과 문서 상태는 별개다. 헤더가 맞아도 크기 제한으로 내부 구조를 검사하지 못했으면 `needs-check / FILE_TOO_LARGE`를 유지한다. OOXML 이름의 OLE 암호화 컨테이너 예외도 유지한다.

## 남은 문제

실제 SSD에서 사라진 본문을 되살리는 새 방식은 이번 수정에 포함되지 않는다. 이전 검색에서 확보한 좋은 복사본을 다음 단계에서 명시적으로 다시 선택하는 기능도 남았다. 이전 시험에서는 같은 파일 기록에서 먼저 정상 본문을 확보했지만 나중 검색에서는 다른 손상 바이트가 읽혔다. 기록번호·세대만으로 과거 파일을 새 결과에 자동 합치면 원본을 잘못 연결할 수 있으므로 이번에는 자동 승계를 넣지 않았다. 각 작업에서 이미 확보한 본문은 해당 작업의 미리보기·저장에 우선 사용한다.

전체 체크리스트의 필수 인수는 19/54(35.2%) 유지. 4단계 기록 재사용 연결 문제와 5단계 F27~F30은 여전히 미완료다.
