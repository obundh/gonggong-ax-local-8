# 0.5.6 — 4단계 보강: 여러 이름 변경 연결과 다음 페이지 지연

파일 이름을 한 번 바꾼 다음 휴지통에 보낸 정상 이력도 0.5.5에서는 모호한 이력으로 처리했다. 0.5.6은 같은 파일 참조·세대에서 이름과 부모 폴더가 연속된 이력을 검증하고 **휴지통 이동 직전 이름**을 복원한다. `초안 → 최종 보고서 → $R… → 삭제`의 복원 이름은 `최종 보고서`다. 가장 오래된 이름을 원래 이름으로 단정하지 않는다.

## 구현 범위

- 이름 변경 OLD/NEW 쌍과 부모 폴더 참조를 순서대로 검증한다. 휴지통에서 꺼냈다가 다시 버린 이력도 연속된 경우 지원한다. 세대·이름·부모 충돌, 중간 누락, 하드링크 변경, 중복 USN, 복수 삭제, 삭제 뒤 사건은 이름 미확인으로 남긴다.
- 한 후보의 이름 판정은 최대 4,096개 사건과 64개 이름 변경 쌍으로 제한한다. 범위 초과를 마지막 이름만 취하는 방식으로 우회하지 않는다. 기존 저장된 근거 형식은 유지하며 마지막 이름 변경 쌍과 삭제 사건을 보존한다.
- 이름만 남은 삭제 이력은 계속 `삭제 이력만 확인`으로 표시한다. 원래 이름이 밝혀져도 본문 위치를 모르면 저장·미리보기를 활성화하지 않는다.
- 같은 필터의 다음 페이지·정렬 변경은 디스크에 계산해 둔 후보 목록을 재사용한다. 후보 추가·수정·제거, 워커의 별도 DB 연결 변경, 다른 reader의 임시 목록 교체를 모두 감지해 무효화한다. 처음 조건을 적용하거나 후보가 변한 경우 전체 필터 계산은 여전히 필요하다.

## 동일 입력 비교

합성 NTFS 이미지와 USN 응답을 양쪽 엔진에 동일하게 제공하고, 후보를 파일로 고정한 뒤 정답과 대조했다. 이름을 연결할 수 있는 4개 사례는 **0.5.5 1/4 → 0.5.6 4/4**였다. 끊어진 이력 1개는 양쪽 모두 확정하지 않았다. 복구 가능한 TXT 본문 1개는 양쪽 모두 정답 SHA-256과 일치했고, 0.5.6은 `최종 본문.txt`로 저장했다. 나머지 4개는 본문이 없는 메타데이터 사례다. 이미지 SHA-256도 불변이었다.

재현 명령:

```powershell
node scripts/verify-stage4b.mjs --baseline <0.5.5 engine 폴더> --output <시험 폴더>
node scripts/benchmark-candidate-paging.mjs --input <고정 후보 JSONL> --baseline <0.5.5 engine 폴더> --current <0.5.6 engine 폴더> --output <시험 폴더>
```

검증 자료: `E:/RecoveryChat-Stage4b-20260926/`. 실제 52,781개 고정 후보의 페이지 결과 전체와 저장된 후보 SHA-256을 비교한다. 이 측정은 목록 처리 성능이며 디스크 검색 시간이나 복구 성공률이 아니다. 다른 자동 시험과 겹친 첫 예비 측정은 성능 대표값에 사용하지 않는다.

이 PC에서 다른 자동 시험을 동시에 실행하지 않은 1회 측정:

| 같은 고정 후보 조회 | 0.5.5 | 0.5.6 |
|---|---:|---:|
| 필터 없는 첫 20개 | 118ms | 145ms |
| 기간 필터 첫 20개 | 8,339ms | 10,207ms |
| 같은 기간의 다음 20개 | 8,566ms | 0.79ms |
| 같은 기간에서 이름순 변경 | 8,914ms | 0.99ms |

개수·순서·점수·후보 정보·일치 개수를 포함한 4개 응답 SHA-256이 모두 같았다. 첫 필터 계산은 개선되지 않았고 이번 측정에서는 더 느렸다. 반복 조회 지연을 제거한 변경이며 화면 렌더링·IPC를 포함한 사용자 체감 시간 측정은 아니다. 영수증: `paging-isolated/paging-sqDA2H/report.json`. 엔진 검증은 419개 통과, Windows 심볼릭 링크 생성 권한 제한으로 1개 건너뜀, 실패 0개다.

## 완료 범위와 남은 일

F21/F23의 일부를 추가로 보강했다. **4단계 전체 인수는 아직이며 필수 기준 17/54(31.5%)를 유지한다.** 삭제된 `$I`, 디렉터리 인덱스 슬랙, `$LogFile` 잔존 기록과 본문 연결은 남아 있다. 실제 SSD의 새 삭제 시험은 이번 변경에서 수행하지 않았다. 최신 실기기 시험은 2026-09-26의 0.5.5 **이력·이름 50/50, 원본 SHA-256 일치 25/50**이며 이 보강의 새 성과로 집계하지 않는다. 이력이 없거나 본문이 읽히지 않는 파일을 생성해 채우지 않는다.

USN의 이름 변경·삭제 이유와 CLOSE 누적 규칙은 [Microsoft USN_RECORD_V2](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/d2a2b53e-bf78-4ef3-90c7-21b918fab304)를 참고했다. 이 기능의 연속성 조건은 잘못된 이름 연결을 피하기 위해 그 위에 추가한 보수적 판정이며 모든 Windows 이력 형태 지원을 뜻하지 않는다.
