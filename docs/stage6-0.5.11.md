# 0.5.11 — 파일 기록 없는 HWP 5 본문 정밀 추출

기존 정밀 검색은 PNG·JPEG·PDF·ZIP 계열의 본문을 찾지만 HWP 5의 CFB 컨테이너는 찾지 않았다. 0.5.11은 선택한 검색 범위 안에 연속해서 남은 HWP 5 컨테이너를 찾아 생성한 `.hwp` 이름으로 추출한다. 삭제 기록·원래 이름을 검색 입력으로 요구하지 않는다. 기존 삭제 기록 검색과 0.5.10의 폴더 단서 한도는 유지한다.

## 지원하는 범위

- CFB v3, 512바이트 섹터, 64바이트 미니 섹터, 헤더 안의 FAT 위치 목록을 지원한다. 외부 DIFAT 확장과 CFB v4는 이번 범위에서 제외한다. 기존 파일당 64MiB 한도와 함께 헤더 FAT 목록 109개 등 더 작은 구조 한도를 적용한다.
- FAT·miniFAT·디렉터리 트리·스트림의 범위, 중복 소유, 순환, 접근 불가능한 항목을 검사한다. HWP의 `FileHeader`, `DocInfo`, `BodyText/Section0`가 올바른 트리를 통해 연결돼 있어야 한다.
- HWP 5 헤더와 지원하지 않는 보호 속성을 검사한다. 문서 스크립트·매크로·외부 연결을 실행하지 않는다. 압축 본문의 의미·문단·서식 전체를 검증하거나 암호를 푸는 기능은 아니다.
- 확인된 모든 저장 구간을 포함하는 최소 컨테이너 끝까지 읽는다. 파일 뒤의 사용하지 않는 패딩 길이는 원래 파일 길이로 확정할 수 없다. 검색 범위 밖의 바이트를 이어 붙이거나 파일시스템에서 조각난 파일을 재조합하지 않는다.
- 별도 작업 폴더로 추출한 뒤 저장본의 구조를 재검사한다. 처음 관측한 헤더·FAT·디렉터리·miniFAT·HWP 헤더의 지문과 다르면 읽을 수 있는 후보로 게시하지 않는다. 이 지문은 원본 본문 해시가 아니다.

## 결과의 의미

`carved-….hwp`는 프로그램이 만든 이름이다. 삭제 이력과 연결하거나 원래 이름을 추정해서 붙이지 않는다. `originalIdentityVerified`, `applicationOpenVerified`, `originalLengthKnown`은 모두 false다. `structuralValidation`에는 컨테이너 구조 검사 및 저장본 재검사만 기록한다. 기존 미리보기는 HWP의 `PrvText`에 한정하며 전체 본문·서식·한컴 앱의 정상 열림 확인과 다르다.

후보가 발견됐다는 것은 지원 구조의 바이트를 추출했다는 뜻이다. 실제 삭제 전 파일과 같은지는 별도 정답 해시가 있는 시험에서만 판정한다. 이미 0으로 읽히거나 덮어써진 본문을 생성해 채우지 않는다.

## 검증

이 버전의 고정 이미지·파서·실제 작업자·배포본 시험 및 독립 검토 기록은 `E:/RecoveryChat-HwpCarving-0511-20260926/`에 보존한다. 자체 구조 시험과 기존 사용자 지정 HWP를 넣은 고정 이미지 시험은 실제 SSD에서 새 파일을 삭제한 시험과 구분한다. 0.5.10의 20/50 실측을 이 버전의 복구율로 재사용하지 않는다.

F32/F34 일부 기능 보강이다. 파일시스템 단편화 재조합·HWP 전체 본문 검증·다른 형식의 모든 변형·실매체 비교 인수는 남아 있으므로 **필수 기준 17/54(31.5%)를 유지**한다. 4단계의 `$LogFile`와 노드 내부 슬랙 등 미완료 항목도 그대로 남긴다.
