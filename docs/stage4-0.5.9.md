# 0.5.9 — 사용 해제된 폴더 인덱스의 이름 흔적

0.5.8이 확인하던 현재 사용 중인 `$I30` 블록의 꼬리 영역에 더해, 폴더 내부 비트맵에서 사용 해제된 블록의 옛 항목과 꼬리 영역도 확인한다. **폴더 기록 흔적**이라는 별도 정보 단서이며 파일의 삭제 사실·원래 전체 경로·본문 위치를 확정하지 않는다. 트리 재배치로 블록이 해제될 수도 있으므로 블록 해제를 파일 삭제로 해석하지 않는다.

## 읽는 범위

- 실제 Windows NTFS 검색에서 이미 발견한 기록·표시할 삭제 이력의 부모 참조만 사용한다. 이미지 제품 검색 경로는 기존 방식이다. 시험에서는 같은 엔진 경로를 고정 NTFS 이미지에 직접 연결한다.
- 기존 본문 후보·삭제 이력·0.5.8의 폴더 슬랙 경로를 먼저 처리한다. 추가 경로에 한도·손상·부모 변경이 있더라도 먼저 검증된 결과는 유지한다. 원본 전체 변경·읽기 실패·취소는 기존 중단 정책을 따른다.
- 추가 경로는 최대 32개 부모, 폴더당 첫 64개 인덱스 위치 중 최대 8개 사용 해제 블록을 읽는다. 할당된 블록은 추가 경로에서 읽지 않는다. 0.5.8 경로는 기존의 첫 8개 위치 제한을 유지한다.
- `$I30` 비트맵의 해당 비트는 **0**, 그 스트림이 차지한 볼륨 클러스터의 할당 비트는 **1**이어야 한다. 폴더에서 쓰지 않는 블록과 볼륨의 미할당 공간은 다른 개념이다. 삭제된 인덱스 스트림, 잘려 나간 구간, 볼륨 미할당 클러스터는 이번 경로에서 읽지 않는다.
- 추가 경로는 최대 4MiB의 루트·비트맵·인덱스 읽기 및 재확인, 별도 1.5초 작업 시간 예산을 사용한다. 보조 MFT·할당 비트맵 I/O는 4MiB 합계에 포함하지 않는다. 기존 폴더 슬랙과 합치면 최대 8MiB의 계수 대상 읽기와 3초의 작업 시간 예산이다. 작업 시간은 처리 경계에서 확인하며 단일 OS 읽기를 강제 중단하는 벽시계 보장이 아니다. 일시정지 시간은 제외한다.
- 한 블록은 최대 64KiB, 블록당 단서는 최대 64개다. 기존·추가 폴더 단서를 합쳐 검색당 128개 한도를 공유하고, 본문 후보·삭제 이력의 보관 한도를 먼저 확보한다. 확인하지 못한 범위와 손상 블록은 경고·통계에 남긴다.

## 근거와 보호 조건

INDX 서명·섹터 fixup·정확한 VCN·헤더와 항목 경계·부모 참조·문자열·크기·시각을 검증한다. 해제 블록에서는 과거 사용 항목도 현재 활성 항목으로 간주하지 않는다. 현재 MFT에서 같은 세대·이름·부모가 확인되는 파일과 현재 루트의 활성 항목은 제외한다. 이전 경로가 이미 찾은 같은 부모 참조·파일 참조·세대·이름은 중복 추가하지 않는다. 이름만 비슷한 후보는 합치지 않는다.

폴더 원시 기록 해시, 스트림 위치·VCN, 원시 블록과 SHA-256, 해제 상태를 나타내는 인덱스 비트맵 바이트·위치를 보관한다. 읽은 폴더·비트맵·블록과 볼륨 할당 상태를 다시 확인한 뒤 결과를 내보낸다. 저장된 후보는 이 근거를 재해석한다. 이는 내부 일관성 검사이며, 모든 근거를 함께 변조하는 공격에 대한 인증이나 원자적 디스크 스냅샷은 아니다.

이름·기록된 크기·기록된 수정 시각을 표시하되 삭제 시각은 미확정으로 유지한다. 본문 준비·미리보기·저장을 허용하지 않으며 정밀 검색 결과와 자동 연결하지 않는다. 이번 보강은 이름 단서의 발견 범위를 늘리는 기능이다.

## 검증과 남은 작업

`E:/RecoveryChat-Stage4e-20260926/`에 0.5.8 소스 스냅샷·해시, 변경 내역, 고정 이미지 비교·엔진·화면·패키지 검증 자료를 보관한다. 같은 이미지에서 옛 사용 항목과 꼬리 항목의 발견 여부를 전후 비교하고, 기존 후보와 복구되는 TXT의 원본 SHA-256, 입력 이미지 불변을 확인한다. 정상·손상 fixup, 잘못된 VCN, 인덱스 및 볼륨 비트맵, 읽는 중 변경, 중복·현재 파일 제외, 첫 64개 위치·8개 블록·읽기·시간 한도와 취소를 별도 시험한다. 최종 수치는 증거 폴더의 `parent-verification.json`에 기록한다.

이번에 실제 사용자 파일을 삭제하거나 SSD 복구율을 재측정하지 않았다. 노드 내부 빈틈, 확장 속성 목록·압축·희소·미초기화 인덱스, 전체 폴더 탐색, `$LogFile`, 본문 연결은 남아 있다. **F22/F23 일부 보강, 필수 기준 17/54(31.5%) 유지**이며 4단계 전체 인수는 미완료다.

형식은 [libyal NTFS 사양](https://github.com/libyal/libfsntfs/blob/main/documentation/New%20Technologies%20File%20System%20%28NTFS%29.asciidoc)의 인덱스·비트맵 구조를 참고해 자체 구현했다. 외부 코드·라이브러리나 사양 본문을 추가 배포하지 않는다.
