# 0.5.5 — 4단계 첫 보강: 삭제 이력 보존과 검색 준비 지연

0.5.4 실제 C: 반복 시험은 원본 3/50건으로 0.5.3 대비 개선되지 않았다. 이번 변경은 파일 기록 재사용으로 목록에서 사라진 삭제 사건을 보존하고, 최근 파일에 접근하기 전 준비 지연을 줄이는 첫 보강이다. 4단계 전체 완료나 원본 복구율 상승을 뜻하지 않는다.

- 현재 MFT 기록과 연결하지 못한 USN 삭제 사건을 별도 `삭제 이력만 확인` 항목으로 남긴다. 파일 참조·세대·저널 ID·삭제 USN을 보존하고, 정확한 이름 변경 쌍이 있을 때만 이전 이름을 연결한다. 과거 이름이 비슷하다는 이유로 다른 파일 본문과 병합하지 않는다.
- 본문 후보를 먼저 등록하고 남은 한도에 이력을 넣는다. 크기 모름은 0바이트로 취급하지 않는다. 이력은 저장·미리보기에서 차단하며, 같은 드라이브의 미할당 영역 정밀 검색으로 이어갈 수 있다. 이 버튼은 특정 이력의 본문 위치를 아는 검색이 아니다.
- 이름 복원 근거가 있는 `$R…` 후보는 확인된 원래 이름으로 검색·정렬한다. 원시 이름과 복원 근거는 그대로 보존하며, 단순한 이전 이름 힌트만으로 일치 판정을 바꾸지 않는다.
- 검색 시작의 원본 장치·작업 공간·저장 위치 검사를 동시에 수행한다. 모든 검사가 끝나고 통과해야 작업 폴더와 워커를 만든다. 장치 신원·물리 디스크 분리·관리자 연결 검사를 생략하거나 이전 검색의 결과를 캐시하지 않는다.
- 삭제 이력은 최대 256개씩 한 트랜잭션에 저장한 다음 화면에 묶음 알림을 보낸다. 본문 후보의 즉시 확보 순서는 유지한다. 저널 입력 최대 50만 사건·후보 최대 10만 건 제한은 유지하며, 전체 과정을 스트리밍 처리하는 구현은 아니다. 보관 후에도 역사적 세대와 이름 변경 근거가 서로 맞는지 재검증한다.

## 검증 범위

동일한 합성 NTFS 이미지와 USN 응답을 0.5.4/0.5.5에 제공했다. 현재 파일 기록과 연결할 수 없는 삭제 이력 5개는 이전 0개에서 이번 5개로 표시됐고, 원래 이름 연결도 5개였다. 해당 5개는 PDF 이름을 가진 이력이며 이 시험에 원본 PDF 본문은 없다. 별도의 복구 가능한 TXT 대조 파일은 양쪽 모두 원본 SHA-256 일치 1/1이었다. 후보를 먼저 고정한 뒤 채점했으며 정답 이름·해시·위치를 검색 입력으로 주지 않았다.

독립된 장치/작업 공간 조회에 각각 300ms를 부여한 준비 시간 비교 3회 평균은 약 638ms → 332ms였다. 실제 C: 전체 검색 시간이나 복구율 측정값이 아니다. 재현: `node scripts/verify-stage4.mjs --baseline <0.5.4 engine 폴더> --output <별도 시험 폴더>`.

엔진·서비스·Electron 화면 검증과 실제 C: 읽기 전용 확인 결과는 `E:/RecoveryChat-Stage4-20260920/`의 최종 인수 보고서에 기록한다. 새 파일 삭제 반복 시험과 기존 삭제 이력 재확인을 구분한다.

기존 10회 시험의 50개 삭제 사건을 실제 C:에서 읽기 전용으로 다시 확인했다. 검색 후보를 먼저 고정한 뒤 과거 시험 기록과 대조했을 때 삭제 이력 50/50개와 원래 이름 연결 50/50개가 확인됐다. 이들은 모두 본문 위치 미확인 이력이며, 이번 확인은 새 파일 삭제나 본문 복구를 하지 않았다. 기존 원본 복구 성적 3/50을 50/50으로 바꾸는 결과가 아니다. 저널 보존 범위 경고가 있어 지정 날짜 전체의 이력을 빠짐없이 읽었다고도 주장하지 않는다.

## 남은 범위

F20/F21/F23/F24의 일부 보강이다. F19~F24는 아직 전체 인수하지 않아 필수 체크리스트는 17/54(31.5%)를 유지한다. 저널이 순환해 사라졌거나 이름 변경 사슬이 복잡·모호하면 원래 이름을 확정하지 않는다. USN은 파일 본문 백업이 아니며, `$LogFile`·디렉터리 슬랙과 본문 카빙의 추가 연결은 남아 있다. 원본 바이트 복구율 향상은 별도의 실제 삭제 반복 시험으로 확인해야 한다.
